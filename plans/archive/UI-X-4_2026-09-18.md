# UI-X-4 - Dr Gallerin's bubble grows to a third of the window's height

Delivered 18 Sep 2026. Was `plans/now/ui-x.md`'s UI-X-4 section.

**Purpose.** Dave, 12 Sep 2026: "Dr Gallerin's bubble should be able to take
up [more] vertical space. make it so it can take up to a third of the height of
the window." His screenshot shows about four lines and a scrollbar.

**Root cause, confirmed.** `UiLayout.gallerin_rect()` already allowed
`command_tray_max_height()`, nearly the full window -- the ceiling was never
tight. `_show_bubble()` sets `visible_characters = 0`, then calls
`_apply_layout()`; `_bubble_label` left `visible_characters_behavior` at
Godot's default, `VC_CHARS_BEFORE_SHAPING`, which shapes only the visible
characters, so the panel's combined minimum height was measured for an empty
line and never re-measured as the line typed out.

**Delivered.**
- `UiLayout.GALLERIN_MAX_HEIGHT_FRACTION := 1.0 / 3.0` and `gallerin_rect()`'s
  height is now `minf(command_tray_max_height(h), h * GALLERIN_MAX_HEIGHT_FRACTION)`.
- `_bubble_label.visible_characters_behavior = TextServer.VC_CHARS_AFTER_SHAPING`
  (set in `_build_bubble()`), so the label shapes the whole line before
  `visible_characters` clips what's drawn -- `_apply_layout()` now measures
  the real minimum height from the first frame. `_show_bubble`'s comment
  records the dependency.
- `gallerin_rect()` takes an optional `avoid: Rect2` (default empty). When it
  is non-empty and shares the bubble's horizontal span, the ceiling shortens
  to `bubble_bottom - (avoid.bottom + PANEL_GAP)`, floored at one line's
  height. `gallerin_panel.gd` reaches the settings window through the
  `"debug_panel"` group (the same pattern `main_menu.gd`'s Settings button
  uses) and re-applies layout from that panel's `visibility_changed` and
  `resized` signals, not `_process`.
- `scenario_actions.gd` gained `close_window` (currently only `"settings"`)
  and four `panel_rect` assertion keys: `height`/`tolerance`, `min_height`,
  `max_height`, `scroll_active` (gallerin only) and `below_panel`/`gap`, for
  fixtures that need a one-sided or exact-height check rather than
  `matches_content`.

**New fixture.** `test_scenarios/uiw4_gallerin_bubble_height_test.json`: at
1920x1080, a short prompt stays under 100px; a 400-character prompt lands
between 90px and 360px; a 2,000-character prompt (forced onto many lines with
literal newlines, so wrapping metrics can't leave it just under the ceiling)
hits 360px±5 with its scroll active; opening the settings window shortens the
bubble to clear its bottom edge by at least 16px, still scrolling; closing it
returns the bubble to 360px±5; at 800x600 the ceiling is 200px±5, still
scrolling.

**Measured discrepancy.** A panel's `get_combined_minimum_size()` comes out
4px under `rect.size.y - UiLayout.panel_chrome().y` once the ceiling is
actually being hit (356px against a 360px ceiling, 196px against 200px) --
the same class of slop UI-X-3 documented for `command_tray`, which is why
that slice's `matches_content` assertions use `"tolerance": 5.0` rather than
the 1.0px default. This fixture's `height` assertions do the same, and do not
attempt to fix `panel_chrome()` itself -- that helper is shared by every
persistent panel's budget, and correcting it is a separate slice.

**Regression.** `tools/verify.ps1` (green, all stages including `doc checks`).
Confirmed the new fixture fails without this change (assert_failed on the
360px height check) and passes with it.

**Completion.** Filed check: "Dr Gallerin's long lines show in full, up to a
third of the screen" (`checks/ready.md`).
