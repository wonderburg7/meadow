# C1-26 — the stage marker asks to be noticed, and says where it is

Shipped 12 Sep 2026. Owner: ChatGPT Codex (Codex lane). Plan:
`plans/now/challenge-1.md`.

## Original specification

**Reasoning level: medium.** One existing marker gains a pulse, and one new
HUD overlay has to avoid the persistent panels.

**Outcome.** A player directed to a marker can find it while it is on screen
or off screen. The shared runner-owned `Polygon2D` remains the sole world
marker; the HUD owns only its screen-space counterpart.

**Requirements.**

1. While the marker is visible, it pulses smoothly using a looping Tween;
   create it on show, kill it on hide, and use unscaled time so it remains
   readable at the 4x speed used in stages 1.11 and 1.14.
2. When a visible marker lies outside the active viewport, show one
   `Stages.MARKER_COLOUR` HUD arrow on the viewport edge, rotated along the
   bearing from screen centre to the marker. Hide it as soon as the marker is
   on screen.
3. Route the arrow around the summary panel, command tray, Dr Gallerin bubble
   and corner readout using `ui_layout.gd`'s existing rectangle owners. If its
   true edge point is covered, slide it to the nearest clear point on that
   edge without changing its bearing.
4. The runner pushes marker global position, visibility and world to the HUD
   through a setter. The HUD does not read or modify the runner's marker.
5. Hiding the marker stops both presentations. A marker in the other world is
   never represented as an off-screen arrow. Challenge 2 and open play show
   neither overlay. The arrow is a lightweight overlay, never a persistent
   bottom-row panel.
6. Recompute only the arrow position each frame, with one world-to-screen
   transform and a bounded edge clamp. Handle camera-follow, resize and an
   exactly-edge marker without flicker; a small inset or hysteresis is valid.

**Save/load.** None; marker and arrow are rebuilt from the current stage.

**Automated acceptance intended.** With the camera far from a marker, the
arrow is visible, aims within a few degrees of the bearing, and intersects no
bottom-row rectangle; with the camera on the marker, it is hidden. The plan
records that Challenge-stage headless coverage is not yet available.

## Delivery record

`challenge_runner.gd` now owns a looping sine Tween which expands the marker
to 1.16 scale and returns it over 1.3 seconds, with time-scale ignored. Its
single visibility helper stops and resets the Tween on hide and publishes the
marker state to `hud.gd`.

`hud.gd` transforms that supplied world point into canvas coordinates each
frame. Its layer-16 triangular arrow is above Dr Gallerin's layer, hides for
the inactive world and for an on-screen marker (with a two-pixel hysteresis),
and slides along the inset viewport edge until clear of visible panel and
corner rectangles.

`tools/verify.ps1` passed (source, balance, function-map, stage-reference and
documentation checks). A direct headless Godot launch crashed in the
environment before scene validation (`0xC0000005`), so the visual result is
filed as hands-on check C-48.

**Hands-on check.** C-48 (`checks/ready/C-48.md`): verify the pulse at normal
and 4x speed, off-screen arrow direction and panel clearance, its return-to-
hidden behaviour, and no arrow on switching worlds.
