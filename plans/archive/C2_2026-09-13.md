# C2 — Challenge goals become data

Shipped 13 Sep 2026. Owner: ChatGPT Codex (Codex lane). Plan:
`plans/archive/architecture-review_2026-09-24.md`.

## Original specification

Level: high. Depends on: C1, A4.

- **Required reading.** This heading. C1's result.
  `scripts/challenge_stages.gd`'s `STAGES_1` and `STAGES_2`.
  `scripts/challenge_runner.gd`'s goal registry, `_goal_met` and
  `_goal_progress`.
- **Files to change.** `scripts/challenge_stages.gd`,
  `scripts/challenge_runner.gd`.
- **Files not to change.** `conditions.gd`.
- **Requirements.** Each stage row gains a `condition` dictionary. The goals
  that are counts or totals lose their `_goal_check_*` method. The goals that
  are not — the ordered visits, the greeting, the stability window, the
  entrance tunnel, selection state — keep theirs behind
  `{"custom": "_goal_check_x"}`. `_build_goal_registry`'s hand-written
  dictionary is deleted, and `custom` resolves by name.
- **Invariants.** Every stage completes on exactly the same condition it does
  today. `GOAL_CADENCE` keeps one entry per goal and A4's three-list source
  check keeps passing. `_goal_progress`'s three numeric bars come from
  `Conditions.progress` and show the same numbers.
- **Automated acceptance.** A headless run of each Challenge fixture reaching
  the same final stage id. A source check that no `_goal_check_*` method
  exists without a `custom` reference naming it.

## Delivery record

Built by Codex on `codex/C2` and merged 13 Sep 2026 (`3c988c6`, finished with
a `FUNCTION_MAP.md`-only follow-up in `4c0e699`, merge `6289216`).

`challenge_stages.gd`'s every stage row in `STAGES_1` and `STAGES_2` now
carries a `condition` dictionary. Count/total goals (`first_cell_built`,
`second_cell_built`, `third_cell_built`, `first_egg_laid`,
`pollen_cell_designated`, and the Challenge 2 raise/reserve/complete goals)
moved to `Conditions` specs such as `{"built_cells_at_least": 2}` or
`{"cell_count": {"designated": "pollen", "explicit": true, "at_least": 1}}`;
the goals that are not simple counts (ordered visits, the greeting, the
stability window, the entrance tunnel, selection state) kept
`{"custom": "_goal_check_x"}`.

In `challenge_runner.gd`, `_build_goal_registry()` and the `_goal_registry`
Callable dictionary it built are gone, along with every `_goal_check_*`
method the new `Conditions` specs replaced (`_goal_check_first_cell_built`,
`_second_cell_built`, `_third_cell_built`, `_first_egg_laid`,
`_nectar_forager_hatched`, `_pollen_foragers_raised`, `_cell_designated`,
`_pollen_cell_designated`, `_interim_reserve`, `_nurse_raised`,
`_c2_complete`). `_goal_met(goal)` now reads the current stage's own
`condition` dict directly — `Conditions.met(main, condition)` for a plain
spec, or a `Callable` built from `condition.custom`'s method name for the
kept predicates — instead of looking `goal` up in the deleted registry.
`_goal_progress` follows the same split, delegating to a new
`_custom_goal_progress(method)` for the two conditions that still report a
numeric bar (`nectar_target`, `pollen_target`); `first_egg_laid`'s bar moved
into `Conditions.progress`'s handling of `brood_cells_at_least` since it is
no longer custom.

`tests/source_checks.py::check_goal_cadence_registry`'s docstring and body
were extended to prove the new shape directly: every stage's `condition`
dict is present, `GOAL_CADENCE`'s keys still match the stage goal ids exactly
(A4's invariant), no `func _build_goal_registry` or `_goal_registry` text
remains in `challenge_runner.gd`, and the `custom` references in
`challenge_stages.gd` name exactly the `_goal_check_*` methods still defined
— no orphan on either side. `FUNCTION_MAP.md`'s `challenge_runner.gd`
description was updated for its reduced line count in the same branch.

`tools/verify.ps1` is green on master with this change in, including source
checks, balance tests, lifecycle tests, the function map, a Godot boot and
the stage reference regeneration. No hands-on check filed — the change is
behaviour-preserving by its own Invariants and every stage's completion rule
is unchanged, so nothing a player sees is different.
