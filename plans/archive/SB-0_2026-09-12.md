# SB-0 — a year-long run reports what a season change actually did

Shipped 12 Sep 2026. `diagnostic_probes.gd`'s `SNAPSHOT_FIELDS` gains
`resources.stored_nectar`, `resources.stored_pollen` and
`environment.flowers_by_species`; the merge bug the third field's sibling
exposed is fixed in the same pass. No check filed -- nothing a player sees
changes.

**Purpose.** SB-1 and SB-2 are balance changes, and `CLAUDE.md` rule 2 says a
balance change is simulated before it ships. Neither could be, because the
fields their comparisons need did not exist.

**Requirements delivered.**

1. `SNAPSHOT_FIELDS` gains the three fields above. The first two read
   `hive.total("nectar")` and `hive.total("pollen")`; the third counts live
   flowers per `species_name`, walking the `flowers` group the way `_snapshot`
   already walks `soil_blocks`.
2. **Required discovery, fixed here.** `selected_snapshot`'s `match` assigned
   a whole sub-dictionary per arm, so two selected fields sharing a group
   clobbered one another (`performance.fps` lost to `performance.top_sections_ms`
   when both were selected). Replaced with a `_merge_field` helper that adds
   one key into the group dictionary, creating it on first use.
3. `DiagnosticLog::_snapshot`'s unconditional `resources` block gains the same
   two totals beside `food_stores`, so a run with no selected profile reports
   them too.
4. `tools/headless/profiles.py`'s `SNAPSHOT_FIELDS` allowlist (the Python-side
   copy the runner validates a scenario's `diagnostics.snapshots.fields`
   against before Godot even launches) is kept in step with the GDScript
   allowlist -- not named in the plan's Files list, but the fixture-selected
   fields would otherwise fail validation before the game ever ran. Its test
   suite (`tests/test_headless_profiles.py`) exercises the same allowlist and
   needed no changes.
5. `docs/headless-run-contract.md`'s "Available snapshot fields" list gains
   the three new names.

**Constraints preserved.** Cadence unchanged. Every existing field keeps its
exact key and meaning; `food_stores` stays ripe honey only, since
`scenario_actions.gd::food_stores_at_least` depends on that reading.
`hive.total()` still runs once per snapshot, never per frame. `hive.gd`,
`flower.gd` and `game_config.gd` were not touched.

**Verified with two throwaway scenario runs** (`tools/run_scenario.py`, not
committed as fixtures -- SB-0's Files list names no `test_scenarios/` entry
and nothing a player sees changes):

- Selecting all three new fields: `session.jsonl` carried
  `{"resources":{"stored_nectar":0.0,"stored_pollen":0.0},"environment":{"flowers_by_species":{...six species...}}}`
  in one snapshot line -- both `resources.*` fields present together.
- Selecting both `performance.fps` and `performance.top_sections_ms`:
  `{"performance":{"fps":1.0,"top_sections_ms":{}}}` -- both keys survived in
  the same snapshot, proving the merge fix.

**Check to file:** none -- nothing a player sees changes.
