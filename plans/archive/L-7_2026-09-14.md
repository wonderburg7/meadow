# L-7 — the queue cannot contradict itself

Shipped 14 September 2026.

**Objective.** `NEXTSTEPS.md` could list an id as both ready (in `## Next
up`) and not startable (in `## Not in the queue, and why`) with nothing to
catch it.

**What shipped.** `check_queue_section_agreement(errors, text=None)` in
`tools/check_docs.py`: it parses the ids in `## Next up` with the existing
item parser, then checks only the bolded lead of each `## Not in the queue,
and why` bullet (never the prose that follows, which legitimately names
other ids as reasons) for a word-boundary match against any of those ids.
A match is an error naming the id. Registered alongside the other queue
checks in `main()`'s doc stage. Two tests added to the existing
`QueueSchemaChecksTest`: `test_an_id_in_both_queue_sections_is_rejected`
(a fixture naming one id in both sections) and
`test_a_prose_mention_of_a_ready_id_is_not_rejected` (a bullet whose prose,
not its bold lead, names a ready id).

**Live contradiction.** The plan's Objective referenced `UI-U-1` sitting in
both sections and a stale `A1`/`A2` paragraph -- both from when this slice
was specified. By the time it was implemented, later slices (C1-23's
retroactive fix, the A2/A3/A4 shipments) had already moved the queue past
both: `NEXTSTEPS.md` at implementation time held no id in both sections, so
there was nothing left to fix. The new check confirms this and will catch
the next occurrence.

**Not a defect.** A fresh worktree's headless Godot boot check fails on
missing `.godot` import cache (`.gitignore`d); this is the known false alarm
L-8 classifies as `import_cache_missing`, not a regression here. `tools/
check_docs.py` and the full `tests/test_source_checks.py` suite were run
directly to confirm this slice's own scope, ahead of that stage in
`verify.ps1`'s pipeline.

**Expected improvement.** The stale-queue class that the 3 September review
ranked critical, and that recurred 9 days later, is now enforced rather than
described.
