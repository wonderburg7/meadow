# D1 — one settings persistence authority (archived 12 Sep 2026)

Owner plan: `plans/design/architecture-review.md`. Both halves shipped
12 Sep 2026; this plan has no further D1 work.

## First half

Every `TUNABLES` row in `scripts/settings_catalogue.gd` gained a `persist`
tag (`run`, `player` or `none`), including 47 new rows for `GameConfig`
fields the catalogue never named at all (F11's 25 saved-but-uncatalogued
keys and 22 fields in neither list), each with no `category` so none of
them gained a visible settings-window control this half didn't intend to
add. `scripts/save_game.gd::saved_settings()` derives the saved-keys list
from the `run` rows in place of the old hand-written `SAVED_SETTINGS`
literal; `tests/source_checks.py::check_settings_persist` proves that
derivation byte-identical to the literal it replaced and fails on a
`GameConfig` field with no row or a `persist` tag pointing at the wrong
object. Nothing about what is saved changed this half, so no
`FORMAT_VERSION` bump and no hands-on check.

## Second half

Applied Dave's three-bucket rule (11 Sep 2026, "Decisions taken 11 Sep
2026" in the owning plan): `disease_on`, `seasons_on`, `rival_hive_on`,
`fog_of_war_on`, `season_length_days` and the three `lay_weight_*` fields
moved from `persist: "none"` to `persist: "run"` in
`scripts/settings_catalogue.gd`, so they now travel with
`save_game.gd::saved_settings()`'s derived list.
`scripts/save_game.gd::FORMAT_VERSION` bumped 4 -> 5.
`scripts/save_migrations.gd` gained `_migrate_4_to_5`, defaulting each of
the eight fields to `GameConfig`'s own value when an older save's
`settings` dict lacks them (`MIGRATED_SETTINGS_V5` names them).
`tests/source_checks.py`'s `ORIGINAL_SAVED_SETTINGS` frozen set and
`tests/test_save_migrations.py`'s Python mirror (`GAME_CONFIG_DEFAULTS`,
`migrate_4_to_5`, and fixture tests for the new step) were updated to
match. `tools/verify.ps1` is green, `python -m unittest
tests.test_save_migrations` passes.

No hands-on check filed: nothing a player sees changes in a fresh save,
and the migration only matters for a pre-existing v4 save, which the
automated fixture tests already cover -- a player wouldn't be able to
tell the difference by playing.

Files touched: `scripts/settings_catalogue.gd`, `scripts/save_game.gd`,
`scripts/save_migrations.gd`, `tests/source_checks.py`,
`tests/test_save_migrations.py`.
