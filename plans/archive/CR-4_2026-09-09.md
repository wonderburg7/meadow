# CR-4 — lifecycle failure-atomic and idempotent

Completed 2026-09-09 from `plans/now/codex-reliability.md`.

Implementation records lifecycle truth in Git and the workstream ledger, with
`status`, `resume`, and pre-merge `abort` commands. Fault injection after every
durable closeout phase proves recovery through `resume`, and a repository lock
serializes master-side lifecycle mutation without making a stale lock file a
manual-repair problem.

Observed at CR-3 closeout on 9 Sep: `git worktree remove` deregistered the
worktree after the merge and push but an external Windows handle kept the
now-empty directory present. The remaining branch and ledger cleanup required
manual recovery; CR-4 makes that cleanup resumable.

Acceptance: inject a failure after every lifecycle phase, rerun `resume`, and
finish with one merge, one clean ledger, no orphan worktree or branch, and no
manual Git repair.

Delivered: `tools/slice.ps1` now derives recovery state from Git and the
ledger, resumes post-merge cleanup safely, and deletes a locally merged slice
branch without requiring an intentionally absent remote branch. The lifecycle
tests inject failures at every durable boundary and cover stale lock recovery.
