# HC-11 — a summary panel's cog offers the fields that panel shows

Archived 10 Sep 2026 from `plans/now/hud-controls.md`. Landed on branch
`claude/HC-11`. Pointer kept there; full spec preserved here.

**Reasoning level: low.** Dave settled the one product question on 9 Sep
2026 (see below), so this is a table and a visibility rule.

**What Dave reported (9 Sep 2026).** "All non-bee summary windows have
settings cogs, but the options only relate to bee summary windows. These
summary window settings should fit the entity."

**Established cause.** `_build_selection_cog()` (`:930`) built one fixed
popup with four items -- identity, energy, activity, trait -- wired straight
to `Session.show_selection_*` and applied by
`_apply_selection_field_visibility()` (`:968`), which touched four Bee-only
labels. The same header, and so the same cog, was used for the cell, soil
and multiple-selection summaries. Nothing filtered it by what was selected.

**Files changed.** `scripts/hud.gd`.

**Files that must not be changed.** Any simulation script. This is
presentation only.

**Requirements.**

1. Describe each summary kind's fields as data -- a dictionary keyed by
   selection kind (bee, cell, soil, multiple), each entry naming its
   toggleable fields, their labels, their `Session` preference keys and the
   `Control` each shows. One table, not four branches.
2. `_build_selection_cog` builds its popup from that table for the current
   selection kind, and `_apply_selection_field_visibility` reads the same
   table rather than four hard-coded labels.
3. A kind with no toggleable fields hides the cog entirely rather than
   showing an empty menu.
4. Existing bee preferences keep their current `Session` keys and their
   current default values, so nobody's saved preferences change.

**Constraints and invariants.** `Session` owns run and UI state; new keys go
there and are saved by `Session.save_preferences()` like the four that exist.
Do not add per-panel preference storage.

**Dave's decision (9 Sep 2026): hide the cog for a cell and a soil block.**
Neither has a line worth toggling, and a cog that opens an empty menu is
worse than no cog. So requirement 3 above is the expected outcome for those
two kinds, not a fallback. Keep the table anyway -- it is what makes adding a
kind's toggles later a data change rather than a fourth branch. The bee panel
keeps its four field toggles with their current keys and defaults.

**Escalate rather than guess if:** hiding the cog leaves the summary header
with nothing in it and the header itself has to go, which changes the panel's
shape rather than its contents.

**Check to file:** one check that the cog's menu differs between a bee, a
cell and a soil block, and that each item hides the line it names.

## What shipped

`SELECTION_FIELD_TABLE` describes each kind's toggleable fields as data:
`"bee"` keeps all four existing items with their existing `Session` keys and
labels; `"multiple"` offers only `"Identity & job"`, since energy/activity/
trait are already blanked for a multi-bee selection and a toggle that hides
nothing was worse than not offering it. `"cell"` and `"soil"` have no table
entry at all, and neither does `"flower"`, `"obstacle"` or `"death"` --
those three showed the same fixed bee cog before this slice despite never
respecting its toggles either, which the plan's own "Established cause" did
not call out but its rationale (Dave's "worse than no cog") covers equally,
so they were folded into "hidden" alongside cell and soil rather than left
showing a cog that still did nothing.

`_build_selection_cog` now only builds the `MenuButton` shell and connects
`id_pressed`; a new `_set_summary_cog_kind(kind)` rebuilds the popup from
the table and sets the cog's visibility, called at every place
`_set_favourite_star` already was (`show_object_summary`, `show_cell_popup`,
`update_selection`'s empty-selection branch, and both branches of
`_refresh_selection_text`) so the cog tracks the summary panel exactly as
the star does. `_apply_selection_field_visibility` reads the same table: a
kind with no entry leaves all four labels unconditionally visible (so
cell/soil/flower/obstacle/death keep showing their own text, which was
never gated by these toggles), and a kind with an entry shows only the
fields it lists, hiding the rest -- so a multi-bee selection no longer
shows three permanently-empty labels. `_on_selection_field_toggled` and
`_field_control` were changed to match; existing bee `Session` keys and
defaults are untouched.

Booted the project (with the primary checkout's `.godot` import cache
copied into the worktree, which a fresh worktree does not have) and
confirmed no parser or type errors. The change introduced two new
NARROWING/shadowed-variable-style warnings (a `name` parameter and a `name`
for-loop variable each shadowing `Node.name`, the same pitfall HC-12
catalogues) -- both renamed to `field_name` before committing; the boot log
after that fix shows only the four pre-existing HC-12 warnings.

`checks/ready/C-36.md` was filed for the hands-on check.

Proof the fix landed: `present: scripts/hud.gd :: SELECTION_FIELD_TABLE`.
