# SB-1 — peak-season production is a rise, not a spike (archived, shipped 12 Sep 2026)

Delivered from `plans/now/season-balance.md`. Full specification preserved
below for provenance; the plan itself now carries only a one-line pointer.

**Reasoning level: medium.** One curve, but it moves every forage rate in
the game, so the headless comparison is the substance of the slice.

**Evidence (Dave, 8 Sep 2026, alongside C-15 passing).** "Increases to flower
resource production in peak season are a bit too high." The panel readouts
themselves are correct — C-15 confirmed the age, season and `+/s` lines all
agree. The complaint is the size of the swing.

**Cause.** `scripts/flower.gd::season_strength()` (~line 297) returned a plain
sine arch that reached exactly 1.0 at the middle of a species' window, while
outside the window it dropped to `GameConfig.out_of_season_strength` (0.05):

```gdscript
func season_strength() -> float:
    if not GameConfig.seasons_on:
        return 1.0
    var f: float = season_fraction()
    if f < season_start or f > season_end:
        return GameConfig.out_of_season_strength
    var span: float = max(0.001, season_end - season_start)
    var through: float = (f - season_start) / span
    # a smooth arch: 0 at both ends, 1 in the middle
    return sin(through * PI)
```

So the in-season peak was twenty times the out-of-season floor, and the curve
was also discontinuous at the window edges: it eased to 0.0 at `season_start`
and `season_end`, then jumped to 0.05 one frame later.

**Delivered.**

1. `scripts/game_config.gd`, `# --- seasons ---` block: added
   `var peak_season_strength: float = 0.75` beside `out_of_season_strength`.
2. `scripts/flower.gd::season_strength()`'s in-window return now arches
   between the out-of-season floor and `peak_season_strength` instead of
   between 0 and 1:

   ```gdscript
       return lerpf(
           GameConfig.out_of_season_strength,
           GameConfig.peak_season_strength,
           sin(through * PI)
       )
   ```

   Interpolating from the floor rather than from zero also removes the old
   discontinuity for free: at `through == 0` or `through == 1` the in-window
   formula now evaluates to exactly `out_of_season_strength`, matching the
   out-of-window return.
3. `scripts/settings_catalogue.gd`, "Seasons & health" category: added a
   `peak_season_strength` row (step 0.05, min 0.1, max 1.5) beside
   `season_length_days`.

`_senescence_scale()`, `out_of_season_ageing_factor`, and
`effective_nectar_rate`/`effective_pollen_rate` were left untouched — they
already multiply `season_strength()` and follow it automatically.

**Simulated before shipping.** `test_scenarios/foraging_evidence_base.json`
(60-day, `seasons_on` default) run twice via
`python tools/run_scenario.py <fixture> --report full`, once with
`peak_season_strength` at its new default 0.75 and once overridden to 1.0
(the old behaviour), same seed both times. Findings:

- Colony survival was identical in both runs: same `game_time` (1180.75),
  `outcome` (`max_days`), `queen_alive` (false) and `total_deaths` (18) —
  the change introduces no new starvation risk on this fixture.
- Peak instantaneous nectar gathering rate (`resources.nectar_rate_avg`)
  fell from 12.26 to 6.85 across the run, confirming the swing is
  genuinely narrower.
- `resources.stored_nectar`/`stored_pollen` (SB-0's new fields) stayed at
  0.0 throughout both runs — this fixture disables auto/proximity
  recruitment to isolate forage-flight mechanics, so the small colony
  consumes everything it gathers immediately rather than building a
  storable surplus, regardless of season strength. No 60-day fixture in
  `test_scenarios/` currently sustains a colony that accumulates hive
  storage across a full year (confirmed by running the already-shipped
  `slice8_senescence_on_seed12345_test.json` unmodified: same zero-storage,
  same collapse pattern) — this is pre-existing behaviour, not something
  this slice introduced, and not in scope to fix here.
- Sampled-rate sums across the whole run (`sum(nectar_rate_avg)` per
  snapshot) fell only ~5%, because a large share of the run's activity
  happens outside the affected window or after the colony's deterministic
  collapse, which the change does not alter.

The curve's edge-continuity was additionally checked analytically: at
`through == 0` and `through == 1`, `sin(through * PI) == 0`, so
`lerpf(floor, peak, 0) == floor` at both edges — exactly matching the
out-of-window return, confirming the discontinuity is gone.

**Acceptance (what Dave does and sees).** With seasons on, watch one species
through its own window with the flower summary panel open. The `+/s` figures
still rise into the middle of the window and fall away at its edges, but the
peak is visibly closer to the shoulder than it was, and the rate no longer
jumps as the window edge passes. Out-of-season flowers are unchanged.
