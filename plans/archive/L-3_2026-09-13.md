# L-3 — branch verification and bookkeeping validation are separate scopes

Shipped 2026-09-13 on `claude/L-3`, merged to master at `c084ebc`.

## Specification (as implemented)

**Objective.** A branch's verification must not fail because of the other
lane's leftover state.

**Non-goals.** Do not delete any check. Every check that runs today still
runs; only where it runs changes.

**Files.** `tools/verify.ps1`, `tools/slice.ps1`.

**Prerequisite.** L-1.

**Algorithm.**

1. Add `-Scope` to `verify.ps1`, a `ValidateSet` of `branch`, `primary` and
   `all`, defaulting to `all` so every existing caller is unchanged.
2. `branch` runs source checks, balance tests, the function map, the stage
   reference and the lifecycle tests. `primary` runs `check_docs.py` only.
   `all` runs both, in the present order and with the present output.
3. In `check_docs.py`, nothing changes. The split is entirely in the caller.
4. In `Invoke-SliceFinish`, call `verify.ps1 -Scope branch` from the worktree
   where it calls `verify.ps1` today. After `Set-Location` to the primary
   root and before the merge, call `verify.ps1 -Scope primary` there. Its
   failure message must say which scope failed and that the branch is
   untouched.

**Tests and failure injection.** In `tests/test_source_checks.py`,
`test_branch_verification_ignores_another_lanes_stale_ledger_row`: builds the
fixture, adds a ledger row naming a worktree that does not exist, and asserts
`verify.ps1 -Scope branch` in the worktree exits zero while
`verify.ps1 -Scope primary` in the primary checkout exits non-zero.

**Proof.** `absent: tools/verify.ps1 :: -Scope` -- now present, so the proof
is satisfied.

**Risk.** Medium. Every caller of `verify.ps1` is affected if the default
changes; it did not -- `-Scope` defaults to `all`.

## Outcome

Implemented as specified, no deviation. `tools/verify.ps1` gained `-Scope`;
`Invoke-SliceFinish` runs `-Scope branch` in the worktree and `-Scope primary`
in the primary checkout before merging, each with a scope-specific failure
message. The new test passed alongside the full suite (32/32 lifecycle tests,
15/15 balance checks, function map and Godot boot all green) before merge.

One unrelated finding surfaced at closeout: `tools/slice.ps1 finish`'s
worktree deletion still failed with "Permission denied" after the merge and
push completed (the directory stayed locked by the just-exited verification
process on Windows) -- this is exactly the defect L-4 exists to fix by moving
deletion out of process and outside the lock. No code change was made for it
here; it is L-4's scope, not a new slice.
