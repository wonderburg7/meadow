# G2 — the dispatcher reads the catalogue (shipped 17 September 2026)

<!-- CONTEXT: archive | LAYER: history -->
Status: archived | Owner: Dave / Codex, integrated by Claude | Verified: 2026-09-17

Shipped on `codex/G2`. `bee.gd::_try_role_work` is now a walk over
`actions.gd`'s rows for the bee's role, each row calling a uniform
`static func <find>(bee: Node2D) -> bool` in that role's `bee_*.gd` module.
The rows are grouped into a per-role array once at load, in a `static var`,
so the think tick does no filtering. The miner's `_mining_no_work_epoch` memo
stays outside the walk, where it still short-circuits the three mining
finders.

## What the integration review changed (Claude, 17 September 2026)

Two behaviour differences were found by reading the diff against master, both
fixed on the branch before merging:

1. **A Stocking comb worker had stopped clearing and evicting.** Master's
   branch ran the cleaning and eviction steps for every `architect_mode`
   except `"build"`, and only the restock and build steps were mode-specific.
   G1's catalogue transcribed the clean and evict rows as
   `modes: ["maintain", "both"]`, which silently dropped both jobs for a
   comb worker set to Stocking. The rows now read
   `["maintain", "restock", "both"]`. The defect entered with G1's data, not
   with G2's dispatcher.
2. **A forager no longer passed through `State.SEEK_FLOWER`.** The catalogue
   row pointed at `BeeForaging.seek_flower`, which perceives a flower
   immediately, so dispatch skipped both the state and the
   `bee_seek_flower` Perf section it is measured in. The row now points at a
   new `start_seek_flower`, which sets the state and returns true, exactly as
   the old `match` arm did. It routes through `autonomous_state`, which the
   old arm did not: that tightens the player-driven invariant
   `bee.gd`'s own comment already claims, and no Challenge stage makes a
   player-driven bee a Forager, so nothing reachable changes.

## Validation

- `tools/verify.ps1` green on the branch, including the Godot boot check and
  `tests/source_checks.py`'s new rule that every `find` named in a row is a
  uniform bool finder in that role's module.
- `python tools/equivalence.py <fixture> master` reports no differences for
  both `test_scenarios/recommendation_slice0_baseline.json` and
  `test_scenarios/colony_30_bees_test.json`.
- The colony summary block in each run's `report.json` -- population by role,
  deaths by cause and role, brood hatches by role/mode, cells completed,
  ripened, cleaned, evicted and restocked, forager deliveries and amounts --
  is identical between master and the branch for both fixtures. That is the
  population/stock/emergence comparison this slice's acceptance asked for;
  `result.json`, which `equivalence.py` compares by default, does not carry
  those fields, which is worth knowing before the next equivalence slice.

## The specification as it stood

### G2 — the dispatcher reads the catalogue

Level: high. Depends on: G1. Must be sole owner of `scripts/bee.gd`.

- **Required reading.** This heading. G1's result. `scripts/bee.gd`'s
  `_try_role_work`, `_idle_dispatch` and `_maybe_break_off_secondary`.
  `.claude/rules/simulation.md`. `.claude/rules/performance.md`.
- **Files to change.** `scripts/bee.gd`, and the `bee_*.gd` module whose function
  a row names, only to give it a uniform signature.
- **Files not to change.** `scripts/hud.gd`, `scripts/challenge_runner.gd`,
  `scripts/orders_zones.gd`; the player-facing surface does not move in this
  slice.
- **Requirements.** `_try_role_work(r)` walks the catalogue rows for role `r` in
  band order, skipping rows whose `modes` exclude this bee's current sub-mode,
  and calls each row's `find` until one returns true. The `match` goes. Behaviour
  is identical.
- **Invariants.** The queen's brood-before-laying exception stays in
  `_idle_dispatch`, where it is today. `role_restricted_to` keeps its current
  meaning until G3. `working_secondary` and the break-off rule are untouched. The
  miner's `_mining_no_work_epoch` memo must survive; it is a documented
  performance contract in `docs/PERFORMANCE_BASELINE.md`, and dropping it makes
  every idle miner walk the soil set every think tick.
- **Implementation guidance.** Land it behind a plain boolean const at the top of
  `bee.gd` so both paths can run in one build, run the equivalence fixture
  against each, then delete the old path in the same commit. Do not leave the
  const behind.
- **Runtime policy.** `_try_role_work` runs on the 8 Hz think tick, unchanged.
  Resolve the catalogue rows for a role once into a static per-role array at
  load, not per call; a linear filter of the whole catalogue on every think tick
  for every bee would be a regression.
- **Automated acceptance.** A headless equivalence run: the pinned baseline
  `test_scenarios/recommendation_slice0_baseline.json` plus
  `colony_30_bees_test.json`, both to a fixed day count, producing identical
  population, stock and emergence summaries before and after. Frame time recorded
  against `docs/PERFORMANCE_BASELINE.md`.
- **Escalation.** Any summary difference at all, however small, stops the slice.
  This is the core loop, and a "close enough" result is a gameplay change nobody
  chose.
