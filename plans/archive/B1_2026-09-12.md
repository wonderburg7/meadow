# B1 — the cell-content catalogue, data only

Shipped 12 Sep 2026. Owning plan: `plans/design/architecture-review.md`
(F2). Branch `claude/B1`, merged to master.

## Original specification

Level: low. Depends on: nothing. Nothing reads the new rows in this slice.

- **Required reading.** This heading. F2 above. `scripts/resources.gd` in full.
  `scripts/hive_cell.gd`'s `capacity_for` and `accepts`.
  `scripts/hive.gd::_content_index`.
- **Files to change.** `scripts/resources.gd`, `tests/source_checks.py`.
- **Files not to change.** every consumer; this slice adds data and changes no
  behaviour.
- **Requirements.** `RESOURCES` gains rows for `honey`, `jelly`, `brood`,
  `corpse` and the empty kind. Each row carries `key`, `label`, `colour`,
  `is_energy`, `energy_factor`, `capacity_config` (the `GameConfig` field name,
  empty meaning `cell_capacity`), `index_bucket`, `storable`, `designatable`,
  `evictable`, `config_flag` and `save_policy`. The existing nectar and pollen
  rows gain the new fields with values matching today's behaviour.
- **Invariants.** `Resources.keys()` must keep returning **only the
  forager-selectable resources**. `roles.gd::count_keys` iterates it to build
  forager tally keys, and adding honey there would invent tally keys no bee can
  have. Add a separate `Resources.content_keys()` for the full list and leave
  `keys()` alone. This is the single most likely way to break this slice.
- **Implementation guidance.** Copy the existing rows' comment style. Take
  `capacity_config` values from `hive_cell.gd::capacity_for`'s current `match`:
  honey to `honey_cell_capacity`, jelly to `jelly_cell_capacity`, everything
  else empty. Take `energy_factor` from `hive.gd::take_energy` — honey
  `honey_energy_factor`, nectar 1.0, everything else 0.
- **Runtime policy.** Static const data; no runtime cost.
- **Automated acceptance.** A `tests/source_checks.py` check that the
  `index_bucket` values in `resources.gd` are exactly the bucket names
  `hive.gd::_content_index` builds, and that `Resources.keys()` still returns
  two entries.
- **Escalation.** None expected. If a kind resists a field, leave the field
  empty and say so in a comment rather than inventing a value.

## What shipped

`scripts/resources.gd`'s `RESOURCES` table gained five rows -- `honey`,
`jelly`, `brood`, `corpse` and the empty kind (`key: ""`) -- alongside the
existing nectar and pollen rows, which gained the same new fields. Values
were taken from the live code as specified: `capacity_config` from
`hive_cell.gd::capacity_for`'s `match` (honey → `honey_cell_capacity`, jelly
→ `jelly_cell_capacity`, everything else empty, meaning
`GameConfig.cell_capacity`); `energy_factor` from `hive.gd::take_energy`
(nectar a fixed `1.0`, honey the *name* of the live tunable
`"honey_energy_factor"` rather than a baked snapshot, since that field is a
runtime `var` reachable from `settings_catalogue.gd`, everything else `0.0`);
`storable`/`designatable`/`evictable` from `hive_cell.gd`'s `space_for`,
`needs_eviction` and the "Reserve for" buttons in `hud.gd` (nectar/pollen/
honey/jelly storable+designatable+evictable; brood designatable only; corpse
and empty neither). `Resources.keys()` was changed from mapping over
`RESOURCES` to a fixed two-entry literal `[NECTAR, POLLEN]`, so it cannot
grow by accident when the table does; `Resources.content_keys()` is the new
full-list accessor, returning all seven keys in table order.

`tests/source_checks.py::check_catalogue_alignment` was narrowed to check
only the two forager-selectable keys against `roles.gd`'s `ROLES` table --
the other five kinds are not forager modes and were never meant to be. A new
`check_resource_content_catalogue` proves `RESOURCES`' `index_bucket` values
exactly match the per-`content_type` buckets `hive.gd::_content_index()`
builds (`""`, `nectar`, `pollen`, `honey`, `jelly`, `brood`, `corpse`),
excluding that function's two derived buckets (`unbuilt`, grouping un-built
cells regardless of content; `ripe_honey`, a honey cell in a particular
state, not a distinct content kind) -- and that `keys()` still returns
exactly two entries.

Nothing outside `resources.gd` and `tests/source_checks.py` changed. Nothing
reads the new rows yet; that is B2 onwards. No hands-on check filed --
nothing a player sees changes, and the acceptance is the automated check
above.

`tools/verify.ps1` is green.
