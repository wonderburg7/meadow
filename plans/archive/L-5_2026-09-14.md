# L-5 — closeout is an idempotent resumable transaction

Shipped 14 September 2026.

**Objective.** One closeout, one recorded phase journal, one push, and the
queue refilled and the specification archived inside the transaction.

**What shipped.** `tools/slice.ps1` gained a JSON phase journal
(`meadow-slice-closeout.json`, beside the lifecycle lock) written after each
of `verified`, `branch-committed`, `archived`, `refilled` and `merged`;
`Invoke-SliceFinish` reads it on entry and skips every phase already
recorded. Two new gated phases sit between `branch-committed` and `merged`:
`archived` refuses to proceed unless `plans/archive/<id>_*.md` exists and the
delivered slice's own heading is gone from its `plans/now/` file; `refilled`
refuses unless the delivered item is gone from `NEXTSTEPS.md`'s `## Next up`
and, unless `Next after:` says the plan is complete, its named successor is
present there. Both edits are still authored by hand, on the branch, before
`finish` runs -- the gate is new, not the authorship. `Invoke-SliceFinish`
now reads the delivered item's own metadata (Title, Check, Plan, Heading,
Next after) from `master`'s committed `NEXTSTEPS.md` via `git show`, not the
worktree's copy, since the branch's own copy has already had the item removed
by the time `finish` reaches it.

`Invoke-SlicePostMergeCleanup` became the single post-merge tail: it now also
regenerates `checks/ready.md` (previously duplicated inline in
`Invoke-SliceFinish`), and pushes exactly once at the end, after the merge,
the ready-index refresh and the ledger-row removal -- replacing the two
separate pushes `finish` made before. `Invoke-SliceResume` and
`Invoke-SliceFinish` both call it, so resuming after any post-merge
interruption always completes the ready-index commit too, which the old
resume path skipped. `Remove-SliceLedgerRow` gained a `-SkipPush` switch so
its push isn't duplicated inside that shared tail.

The end-of-slice report's `Next slice`, `Other lane` and `Start it with`
lines are now lookups: `Get-SuccessorId` parses the leading token off
`Next after:`, and both `master`'s post-merge `NEXTSTEPS.md` and its
`## Copy-paste prompts` section are read back to fill them in, instead of
telling the session to work them out by hand. A diffstat of the merge
(`git diff --stat <pre-merge-HEAD> master`) is printed with the report.

`CHATGPT.md`'s "update `NEXTSTEPS.md` on master, never on the branch" rule
and its "`finish` does not refill the queue" paragraph are rewritten for the
new contract; `CLAUDE.md`'s matching sentence in "Coordinating and closing
out workstreams" is updated the same way.

**Tests.** `tests/test_source_checks.py`'s
`test_resume_completes_every_durable_finish_phase` and
`test_finish_is_resumable_after_every_injected_phase` both gained `archived`
and `refilled` in their injected-phase lists, and every fixture that calls
`finish` now performs the archive-and-refill edit first (`write_refill`
helper) to satisfy the new gates. Two new tests:
`test_closeout_pushes_exactly_once` counts `refs/heads/master` reflog entries
on a local bare remote across one `finish` call and asserts exactly one;
`test_refill_promotes_the_named_successor` runs a two-item, single-lane
queue through the full archive/promote/finish path and asserts the queue is
one item shorter, the successor leads, and the specification moved.

**Fixed along the way.** `Invoke-SlicePostMergeCleanup`'s
`git worktree remove --force ... 2>$null` was redirecting a native
command's stderr under `$ErrorActionPreference = "Stop"`, which turns
PowerShell 5.1's own wrapping of a redirected stderr line into a terminating
exception -- surfacing exactly the "directory could not be deleted" case the
following `$LASTEXITCODE` check exists to handle as an uncaught error
instead. Only exercised once `finish`'s own worktree removal started routing
through the same shared tail as `resume`'s; the redirect is removed.

**Proof.** `present: tools/slice.ps1 :: queue not refilled by 'finish'` --
holds no longer, which is the fix: closeout now gates on the refill instead
of skipping it.

**Verification.** `tools/verify.ps1 -Scope branch`'s source-check and
balance-check suites and `tests/test_source_checks.py` (37/37) are green.
The Godot compile-check stage failed in this worktree with
`Could not preload resource file
"res://assets/sprites/environment/wax.cell.empty.png"` -- a missing `.godot`
import cache in a fresh worktree, not a defect in this slice's files (see
`docs/known-pitfalls.md`); `tools/check_docs.py` run directly reports only a
pre-existing stale ledger row for another lane's worktree (`.worktrees/C4`,
registered by a concurrent Codex session) and two pre-existing plan
line-count warnings, neither touched by this slice.
