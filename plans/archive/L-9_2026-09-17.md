# L-9 — the floor is measured and split, and this plan is gated

Shipped 17 September 2026.

**Objective.** W-2 targeted a session-opening floor of 45,000 tokens, never
measured itself, and the floor had drifted to 77,322. Split the measurement
into what the repository owns and what it does not, add the phase split F13
reports, and check the plan's completion gate against both.

**What shipped.** `tools/session_cost.py` gained `--phases`, a four-row table
(requests, context, share) bounding each session's assistant requests around
its first and last edit to a file under `scripts/`, `scenes/`, `shaders/`,
`tests/`, `tools/` or `test_scenarios/` — before the first such edit,
between first and last (implementing), after the last, and whole for a
session with none. Reproduced against 4-12 September 2026 within 10% of
F13's figures (49.1/23.1/18.1/9.6% against F13's 47.1/25.6/17.4/9.9%).

`--days N`'s session-opening figure is now split into `repository context`
(tokens from `Contents of <path>` blocks — CLAUDE.md, memory, rules files —
inlined into the opening turn, whose path falls under the session's own
repository/worktree root) and `host context` (the remainder: system prompt,
tool schemas, MCP/plugin/skill listings, none of which is logged directly,
so host context is recovered as `total - repository`, not measured on its
own). Token counts use a 4-characters-per-token estimate, stated in the
module docstring at `PRODUCT_DIRS`/`_CONTENTS_MARKER` so a later reader can
judge the heuristic. The existing single-figure `session-opening context`
line is unchanged.

**Record.**

| Measurement | Total | Repository | Host |
| --- | --- | --- | --- |
| 3 Sep 2026 before (no split existed) | 61,558 | -- | -- |
| 12 Sep 2026, reconstructed over its own window | 77,322 | 3,990 | 73,323 |
| 17 Sep 2026 after, this session's `--days 1` | 64,614 | 4,144.5 | 60,469.5 |

The after figure is a two-session median, moving toward the 45,000 target
but far too small a sample to call it met.

**Completion gate, checked 17 September 2026.** Three of four conditions are
unmet:

1. Met — the before/after figures above were produced by
   `python tools/session_cost.py --days 1`, run in this session (opened
   after L-5 merged).
2. Not met — `python tools/session_cost.py --days 7 --classify` shows 44
   `lifecycle_failure` outcomes, not zero.
3. Not met — no canary slice has been named by either lane under the
   post-L-5 configuration yet.
4. Not met — `--phases` over the seven sessions since L-5 merged
   (14-17 Sep) gives an implementing share of 40.0%: the threshold itself,
   not above it, on a seven-session sample against F13's 72.

**Expected improvement.** W-2's failure mode — a target set against a number
the repository could not move, and never checked — cannot repeat: the split
and the phase table now exist and were checked against live evidence in the
same session that built them.

**Next slice.** None. L-9 was this plan's last piece of code; the
completion gate needs evidence from ordinary future sessions, not more
implementation. The plan stays `active` in `plans/now/agent-lifecycle.md`
until all four gate conditions hold at once.
