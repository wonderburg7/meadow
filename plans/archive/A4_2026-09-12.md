# A4 — wire the goal cadence

Status: archived | Shipped: 2026-09-12 | Source: `plans/archive/architecture-review_2026-09-24.md`

## Original specification

Level: medium. Depends on: A3 for the full benefit, but lands without it.

- **Required reading.** This heading. F4 (`plans/archive/architecture-review_2026-09-24.md`).
  `scripts/challenge_runner.gd`'s `_process`, `GOAL_CADENCE`, `_goal_met` and
  `_build_goal_registry`.
- **Files to change.** `scripts/challenge_runner.gd`.
- **Files not to change.** `scripts/challenge_stages.gd`, `scripts/hive.gd`.
- **Requirements.** `_process` consults `GOAL_CADENCE` for the current stage's
  goal. `frame` runs every frame as now. `poll` runs at 4 Hz. `event` runs when
  `hive.index_epoch` or `main._population_epoch` has moved since the last check,
  with 4 Hz as a backstop. Challenge 2's `_c2_nectar_low_seen` sampling moves
  onto the same 4 Hz tick.
- **Invariants.** Every goal id in `challenge_stages.gd` has a `GOAL_CADENCE`
  entry; a missing one is an error, not a silent `frame` default. The
  ordered-visit goals and the greeting and hearts beats stay on `frame`.
  `_advance()` still runs in the same frame the goal is first seen met.
- **Implementation guidance.** One `_goal_poll_timer` on the runner, reset to
  0.25 s. Keep `_goal_met` as it is and gate the call site. Do not change any
  predicate body in this slice.
- **Runtime policy.** As stated above: 4 Hz for `poll` and `event`, per frame
  for `frame`. Worst-case goal latency 250 ms, which no stage's text implies is
  too slow.
- **Automated acceptance.** Add a `tests/source_checks.py` check that the goal
  id sets in `challenge_stages.gd`, `GOAL_CADENCE` and `_build_goal_registry`
  are identical — this is the three-lists problem, and the check is cheaper than
  the collapse in C2. Run an existing Challenge scenario fixture and confirm the
  same stage sequence completes.
- **Escalation.** If any stage completes in a different order, stop and report
  which. A stage that needed per-frame detection is a design fact worth
  recording, not a cadence to widen.

## What shipped

`scripts/challenge_runner.gd`'s `_process` now gates its per-stage goal
check on `GOAL_CADENCE`, via a new `_should_check_goal(goal_id, goal_tick_due)`:

- `frame` goals check every `_process` call, unchanged.
- `poll` goals check only when a new `_goal_poll_timer` (`GOAL_POLL_INTERVAL
  := 0.25`) reaches zero.
- `event` goals check early the moment `hive.index_epoch` or
  `main._population_epoch` differs from the value last observed at a poll
  tick (`_goal_checked_index_epoch`/`_goal_checked_population_epoch`), or
  fall back to the same 4 Hz tick if neither epoch moved.

A goal id with no `GOAL_CADENCE` entry falls back to checking every frame,
with a `push_error` naming the missing id — loud, not a silent default.

Challenge 2's `_c2_nectar_low_seen = min(...)` sampling (previously run every
frame) now only samples on the same `goal_tick_due` tick.

`tests/source_checks.py::check_goal_cadence_registry` extracts the goal id
set from `challenge_stages.gd`'s `"goal": "..."` entries and from
`challenge_runner.gd`'s `GOAL_CADENCE` and `_build_goal_registry` dict
literals via regex, and fails if any two of the three sets differ.

`test_scenarios/h4_challenge1_stage_advance_test.json` (a `--scenario`
headless run through Challenge 1 to stage 1.14 via `advance_challenge_stage`)
passed both before and after, with no `SCRIPT ERROR`/compile-failure lines in
`process.log` on the post-change run.

`tools/verify.ps1` is green, including a fresh `godot compile check`.
