# UI-T-6 — the command tray fills its rectangle again, and the bottom row keeps its gaps

<!-- CONTEXT: plan-archive | LAYER: provenance -->
Status: shipped 2026-09-08 | Owner: Dave / Claude Code

Shipped from `plans/now/ui-bottom-row.md`. This was the last open slice in
that plan, which is now complete -- see `plans/now/ui-bottom-row.md` for the
one-line pointer and `NEXTSTEPS.md` for what replaced it in the Claude lane.
Check: C-18 in `checks/ready.md`.

**Reasoning level: medium.** Two bounded changes in one file, both with a
named cause and a stated correct expression. It blocks C-5 and C-7 and the
back half of every Challenge run, so it is the highest item in its lane after
UI-Q-3.

**Evidence (Dave, 8 Sep 2026, C-18).** "The command bar now appears as a flat
bar at the bottom of the screen. It doesn't go off screen, which is good, so
the lowest level of the panel is correct, but it is only a few pixels high
and doesn't display any buttons/choices." And: "Width seems appropriate at
different screen sizes, but the summary window still overlaps and there's no
16px gap between the summary window and command panel."

**Fault 1 — the tray is capped to zero.** `_resize_command_tray` read

```gdscript
var content_height: float = command_scroll.get_combined_minimum_size().y
command_scroll.custom_minimum_size.y = minf(content_height, ceiling)
```

`command_scroll` is a `ScrollContainer` with
`vertical_scroll_mode = SCROLL_MODE_AUTO`. Godot omits a child's minimum on
any axis a ScrollContainer can scroll, so `get_combined_minimum_size().y` is
approximately zero however much the tray holds. The cap was therefore set to
zero every time and the tray rendered as its own chrome.

**Fix 1, as shipped.** `command_scroll`'s one child -- the `VBoxContainer`
built in `_build_command_tray` as `column` -- is now kept as the
`command_content` field, and `_resize_command_tray` measures
`command_content.get_combined_minimum_size().y` instead of measuring the
scroller. `ceiling` (a budget for the panel's outer rectangle) has the
panel's own chrome subtracted before the `minf`, via the new
`UiLayout.panel_chrome_height()`.

**Fault 2 — the summary panel could grow through its gap.**
`_apply_selection_tray_width` set only
`selection_panel.custom_minimum_size.x` and
`selection_column.custom_minimum_size.x` to `width`. `custom_minimum_size` is
a floor, so a child whose own minimum width was larger -- the cog row, a soil
button, an unwrapped word -- made the panel wider than the floor and pushed
it over the tray.

**Fix 2, as shipped.** `_apply_selection_tray_width` now also sets
`selection_panel.size.x = width` so the anchored panel takes the width
immediately, and caps `selection_column.custom_minimum_size.x` to
`width - UiLayout.panel_chrome_width()` (a new function alongside
`panel_chrome_height()`) rather than to the panel's outer width.
`soil_mark_btn`, `soil_clear_btn` and the selection cog `MenuButton` were
given `autowrap_mode`/`clip_text`/a fixed `custom_minimum_size.x` of 24
respectively, so no single child can raise the column's minimum width past
the space it has been given.

**Not changed.** `UiLayout.command_tray_width`, `command_tray_left_edge` and
`selection_tray_width` -- Dave confirmed the widths are right at every screen
size, and all three are pure functions with balance tests behind them. What
the tray contains and `more_panel`'s open/close behaviour are unchanged.

**Verification.** `tools/verify.ps1` (source/type checks, balance suite,
function map, docs) is green. The gap arithmetic
(`selection_panel.position.x + selection_panel.size.x + SELECTION_TRAY_GAP <=
command_tray.position.x`) is expressible against `ui_layout.gd`'s pure
functions, but this codebase has no harness that executes GDScript static
functions from the Python test suite -- `tests/source_checks.py` is a static
text scanner, not an interpreter -- so writing it there would mean
duplicating the formula as a second, driftable copy rather than testing the
real one. Left to C-18, which asserts the same geometry live at three
viewport sizes.

Dave's 8 Sep report added: the tray shows its Job/Focus/Orders buttons at
