# L-4 — the worktree is deleted out of process, outside the lock

Shipped 2026-09-14. Part of `plans/now/agent-lifecycle.md`.

**Objective.** Remove the 60-attempt, 3-second retry loop from inside the
lifecycle lock. Deletion happens after the process holding the directory has
exited.

**Non-goals.** Do not try to identify or kill whatever holds the directory
beyond the existing `Godot*` stop. Do not leave a registered worktree behind:
git's own bookkeeping must be correct even when the directory survives.

**Files.** `tools/slice.ps1`.

**Prerequisite.** L-3.

**Algorithm.**

1. In `Invoke-SliceFinish`, replace the retry loop with: `git worktree
   remove` once; if the directory still exists, `git worktree prune` so git's
   records are correct, then write the path into a queue file
   a queue file beside the lifecycle lock, named meadow-slice-pending-deletions (one path per line, appended, no
   duplicates) and continue. Closeout does not fail because a directory
   survived.
2. Add a `Remove-PendingWorktreeDirectories` function, called at the start of
   every `start`, `finish`, `resume` and `doctor`, before the lock is taken.
   It reads the queue file, tries `Remove-Item -Recurse -Force` on each path
   once, and rewrites the file with only the paths that still exist.
3. `doctor` reports the queue as a `pending_deletions` array so a surviving
   directory is visible rather than silent.
4. `check_docs.py`'s orphan-directory check must not fail on a directory
   listed in the queue file. Read the queue file, skip those paths, and say
   so in the check's message.

**Tests and failure injection.** Added
`test_finish_completes_when_the_worktree_directory_cannot_be_deleted`: holds
an open file handle inside the fixture worktree, runs `finish`, asserts it
exits zero, asserts the branch merged and the ledger row is gone, asserts the
path is in the queue file, and asserts `check_docs.py` passes. Then releases
the handle, runs `doctor`, and asserts the directory is gone and the queue
file is empty.

**Proof.** `present: tools/slice.ps1 :: $maxAttempts = 60` (removed by this
slice).

**Risk.** High. It changes what "closeout succeeded" means. The invariant
held: git's worktree registry and the ledger are always correct; only the
directory may lag.

**Outcome.** Shipped as specified: `Invoke-SliceFinish` now attempts one
`git worktree remove`, falls back to `git worktree prune` plus a
`meadow-slice-pending-deletions` queue file beside the lifecycle lock, and
`Remove-PendingWorktreeDirectories` retries that queue at the start of
`start`, `finish`, `resume` and `doctor`. `doctor` reports the queue as
`pending_deletions`. `check_docs.py -> check_workstreams` skips queued paths
as a warning rather than an orphan error. `tools/verify.ps1` was green
(source checks, balance tests, function map, godot boot, stage reference,
documentation checks) before merge. This slice's own closeout exercised the
new path for real: the worktree directory could not be deleted immediately
(the session's own shell was still inside it) and was queued and cleared on
the next `doctor` call, exactly as designed.

**Next slice.** L-5.
