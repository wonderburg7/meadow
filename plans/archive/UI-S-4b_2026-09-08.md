# UI-S-4b — a double right-click stops closing the bee panels

<!-- CONTEXT: plan-archive | LAYER: on-demand -->
Status: shipped 2026-09-08 | Owner: Dave / Claude Code | Verified: 2026-09-08

**Shipped.** `plans/now/ui-bottom-row.md`'s UI-S-4b slice, filed 8 Sep 2026
against C-14's failure, is done. Kept here as provenance only.

## What shipped

1. `scripts/input_selection.gd::_unhandled_input` now ignores the duplicate
   `pressed` event Godot delivers for a fast second right-click
   (`event.double_click == true`), so `_issue_command` runs once per
   double-click instead of twice.
2. `scripts/diagnostic_log.gd` gained `log_selection_panels_hidden(source,
   shown_count, selected_count)`, logged on every true -> false transition of
   `selection_panel.visible` or `command_tray.visible` in
   `scripts/hud.gd::update_selection` and `::_refresh_selection_text`.
   `show_cell_popup` never sets either flag false in the current source, so
   it needed no call.

## Why (symptom and diagnosis)

**Symptom (Dave, 8 Sep 2026, C-14).** A double right-click still clocked off
the bee summary window and command panel after UI-S-4 shipped, on any bee.

**What the diagnostic log proved.** UI-S-4's `command_issue` entries,
recovered from a 7 Sep 2026 session log, showed every right-click recording a
correct `selected_count`, `commandable_count` and state transition -- the
selection was never lost and the command was never refused. The two panels
were being hidden while the selection behind them stayed intact, which ruled
out UI-S-4's theory and pointed at the input boundary instead: Godot's
duplicate `double_click` event running `_issue_command` twice.

## Acceptance (met)

Select any bee. Right-click twice in quick succession on a point in the
meadow, on a flower, on the hive marker, and in the hive view on a comb cell.
In every case the bee stays selected, its summary panel and command tray stay
open, and one command is carried out. Right-clicking twice slowly still works
as before.
