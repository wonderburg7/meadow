# WD-0 — the workflow diagnostic log and its reader

Landed 17 September 2026 on `claude/game-diagnostics-logging-dba39e`.
Live plan: `plans/now/workflow-diagnostics.md`.

## Why

A review of the development system on 17 September 2026 found that
`tools/session_cost.py` could report what a *window of sessions* cost but
nothing could report what a *slice* cost, and that every automated failure --
a `slice.ps1` stop, a `verify.ps1` stage, a headless run -- was printed once
and then discarded. Reviewing how the system was running therefore meant
reading transcripts, which is the most expensive thing a session can do.

The requirement was that measuring must cost the model nothing: scripts write
the events, and the log is read only when someone asks.

## What shipped

**The spine.** `tools/diagnostics.ps1` (`Write-Diagnostic`, `Get-DiagnosticsPath`)
and `tools/diagnostics.py` (`write_event`, `read_events`, `log_path`, `KINDS`)
append one JSON object per line to `<git-common-dir>/meadow-diagnostics.jsonl`
-- the same directory `Invoke-WithLifecycleLock` and `Get-ClosingJournalPath`
already use, so the file is shared by every worktree and never committed, and
the two lanes cannot conflict over it. Schema: `ts`, `kind`, then whatever
fields the caller has. String fields are truncated at 300 characters; the file
rotates to `.jsonl.1` past 1 MB. Both writers swallow every error: a log that
could break `finish` would cost more than it ever measured.

**Emitters.**
- `tools/slice.ps1` dot-sources `diagnostics.ps1` and records `slice_stop`
  from `Write-SliceFailure` -- the one point every stop already passes
  through -- plus `slice_claimed` at the end of `Invoke-SliceStart` and
  `slice_finished` at the end of `Invoke-SliceFinish`. `slice_claimed`
  carries the branch, which is the join key: a transcript records neither the
  slice id nor the level it was advised at.
- `tools/verify.ps1` records `verify_stage` from `Write-StageResult`, with the
  stage's duration. The three parallel stages are timed from the job's own
  `PSBeginTime`/`PSEndTime` rather than a stopwatch each. The non-`-Quiet`
  job branch, which prints directly instead of calling `Write-StageResult`,
  records its own event so a plain run is not missing from the log.
- `tools/hook_log.py`, wired to `SessionStart` and `Stop` in
  `.claude/settings.json`, records `session_start`/`session_end` with the
  session id and branch. It prints nothing and exits 0 whatever happens: a
  hook's stdout is fed into the model's context.

**The reader.** `python tools/session_cost.py --events` prints the window and
event counts, slices claimed/finished, lifecycle stops grouped by
command-and-step, verify stages run, verify failures by stage, per-stage
median durations, and cost by branch. `--days`, `--classify` and `--phases`
are untouched, so L-9's published baselines still reproduce.

## Decisions taken, so they are not re-argued

- **The log is not committed.** Committing it would conflict between the two
  lanes on every slice. The cost is that it is lost on a re-clone and is
  per-machine; that was judged the right trade.
- **`--events` globs every `~/.claude/projects/C--Users-dl13860-Documents-Meadow-meadow*`
  directory** for its session join, because a worktree session's transcript
  lands in its own directory keyed by the worktree path. The other modes keep
  reading the primary directory alone: their baselines were measured that way
  and widening them silently would move the numbers.
- **`log_path` and `_branch` both fall back to the process's own directory**
  when the root they are handed does not resolve under git. A hook is handed
  a working directory by its host, and a form git cannot resolve would
  otherwise drop the event with no trace.

## What it found in its first run

`lifecycle tests` has a median of 270 s and is the dominant cost of every
`verify.ps1` run; the next slowest stage, `godot boot`, is 8 s. That was not
visible before this slice and is not acted on here.

## Incidental

The lifecycle suites copy a subset of `tools/` into a fixture repository, so
`tests/workflow_test_support.py` gained `DIAGNOSTICS_PATH` and both
`tests/test_slice_lifecycle.py` and `tests/test_two_lane_closeout.py` now copy
`tools/diagnostics.ps1` alongside `slice.ps1` and `verify.ps1`. Without it
every lifecycle test failed at the dot-source.

This worktree was opened by the desktop app rather than by `slice.ps1 start`,
so it had no `.godot` import cache and `verify.ps1`'s `godot boot` stage
failed with parse errors that looked like product breakage -- the pitfall
`docs/known-pitfalls.md` records. Copying the primary checkout's `.godot` in,
which is what `Invoke-SliceStart` does for a slice worktree, made the stage
pass with no code change.
