# CR-2 — make the standard runtime self-discovering

Status: shipped 2026-09-09 | Plan: `plans/now/codex-reliability.md`

## Specification

Small Windows tooling slice.

1. Extend `verify.ps1::Resolve-Python` to locate the bundled interpreter from
   the running Codex PowerShell dependency tree when ordinary `PATH` lookup
   fails. Keep `-PythonPath` as the explicit override.
2. Thread `-PythonPath` through `slice.ps1 finish` for non-Codex callers and
   tests, even though normal Codex use should need no argument.
3. Add a `doctor` check for Python, Godot, Git identity, repository ownership,
   remote reachability when a push will be required, and Git-metadata write
   capability. Report all failures together.
4. Add a project local-environment setup/action for the canonical verification
   command so a worktree starts with the same toolchain every time.

Acceptance: verification and closeout succeed in a clean Codex task with no
PATH edits, aliases, runtime search, or generated bytecode left in the tree.

## Delivered

`verify.ps1` discovers the bundled Python beside the injected
`codex-primary-runtime` dependency paths after ordinary command lookup, while
`-PythonPath` remains the first-choice override. `slice.ps1` passes that
override through closeout and its `doctor` reports Python, Godot, Git identity,
repository ownership, remote reachability and Git-metadata write failures
together. `.codex/environment.toml` runs the canonical verifier during Windows
worktree setup and exposes the same command as a toolbar action. Verification
suppresses generated Python bytecode.

## Evidence

- Six focused runtime, doctor and local-environment regressions passed.
- `tools/verify.ps1` passed without `-PythonPath` or a PATH edit.
- Low risk: tooling, project configuration, tests and plan documentation only;
  no gameplay, save, dependency or player-facing behavior changed.
