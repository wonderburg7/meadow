## Implementation block: E20-1

1. **Outcome and owner**: Candidate Jules task to add a structured failure summary table in `tools/run_tests.py`.
2. **Files**: `tools/run_tests.py`, `tests/test_run_tests_helpers.py` (`free` in preflight).
3. **True now**: `tools/run_tests.py::run_all` returns `tuple[list[str], dict[str, float]]`. When a worker fails, it prints `FAILED ... (exit N)` and dumps `result.stdout` and `result.stderr` immediately to the console. At the conclusion of `main`, the runner iterates over `failed` printing: `failed: <test_id> -- rerun alone with: python -m unittest <test_id>`. In a run with 200+ tests and multiple failures, finding the actual assertion or exception requires scrolling back through long interleaved logs. Baseline command: `python tools/run_tests.py --private-user tests.test_heading_helpers tests.test_nonexistent_xyz`.
4. **Do**:
   - In `tools/run_tests.py`, add a helper `extract_failure_reason(stdout: str, stderr: str) -> str` that parses the last exception line or failing assertion line (e.g. `AssertionError: ...`, `ModuleNotFoundError: ...`, or `ERROR: ...`).
   - Update `run_all` to record failure reasons alongside failed test IDs: `tuple[list[str], dict[str, float], dict[str, str]]`.
   - In `main`, print a formatted summary section before the rerun commands:
     ```
     Failed summary:
       - <test_id>: <extracted_reason>
     ```
   - In `tests/test_run_tests_helpers.py`, add test cases validating `extract_failure_reason` on standard unittest exception outputs and asserting that `main` formats the summary.
5. **True afterwards**: Running `tools/run_tests.py` on failing tests displays the exact failure reason in the summary block at the bottom of the output, avoiding manual log hunting.
6. **Must retain**: Complete worker stdout and stderr output; thread safety with `print_lock`; timing measurements; exit code 1 on failure.
7. **Verify**: `python -m unittest tests.test_run_tests_helpers` and `python tools/run_tests.py --private-user tests.test_heading_helpers tests.test_nonexistent_xyz`.
8. **Saving and cost**: Avoids 400-1,200 tokens of trace scanning per failing test run. Total runtime overhead is negligible (<1 ms).
9. **Reasoning**: Low risk test harness enhancement. Stop if: parsing output alters subprocess return code handling or worker thread parallelism.
10. **Reviewer entry point**: Inspect `tools/run_tests.py::run_all` and `tests/test_run_tests_helpers.py`.

## Implementation block: E20-2

1. **Outcome and owner**: Candidate Jules task to support targeted script filtering in `tests/source_checks.py`.
2. **Files**: `tests/source_checks.py`, `tests/test_source_checks.py` (`tests/source_checks.py` owned in live slices, but candidate Jules task can be scheduled once free).
3. **True now**: `tests/source_checks.py::main` unconditionally reads all files matching `os.path.join(ROOT, "*.gd")` and executes both file-level checks (declarations, calls, brackets, indentation, etc.) and global repository-level checks. When an agent is iteratively fixing an issue in a single script, it cannot restrict file-level static checks to just that script.
4. **Do**:
   - In `tests/source_checks.py::main`, parse optional positional script paths from `sys.argv[1:]`.
   - If specific paths are provided, run file-level checks (e.g. `check_declarations`, `check_calls`, `check_brackets`, `check_indentation`, `check_duplicates`) solely on the specified files, and skip repository-wide catalogue checks unless requested with `--all`.
   - Print clear targeted output: `checked N specified scripts -- names, calls, brackets all OK`.
   - In `tests/test_source_checks.py`, add test verifying single-script execution returns clean status and catches syntax errors in the targeted script.
5. **True afterwards**: Running `python tests/source_checks.py scripts/bee.gd` verifies the file in <0.05s without checking unaffected scripts.
6. **Must retain**: Default behavior with no arguments checking all 109 scripts and running all global catalogue validations.
7. **Verify**: `python tests/source_checks.py scripts/bee.gd` and `python -m unittest tests.test_source_checks`.
8. **Saving and cost**: Saves ~800-2,000 tokens of extraneous diagnostics during iterative script development; speeds up local developer feedback loop.
9. **Reasoning**: Low risk developer tooling enhancement. Stop if: selective file checks allow broken cross-script calls to pass silently without warning.
10. **Reviewer entry point**: Inspect `tests/source_checks.py::main`.
