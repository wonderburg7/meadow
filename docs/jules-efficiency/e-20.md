## Implementation block: E20-1

1. **Outcome and owner**: Candidate slice under `plans/now/code-health.md` (which owns `tests/source_checks.py`) to add targeted check name filtering to `tests/source_checks.py::main`.
2. **Files**: `tests/source_checks.py` (`owned` by `plans/now/code-health.md` and `NEXTSTEPS.md`).
3. **True now**: `tests/source_checks.py::main` unconditionally executes every check function over all 109 GDScript files and progression/catalogue sources. There is no CLI argument parsing (`sys.argv` is ignored). Running `python tests/source_checks.py check_calls` runs the entire suite of 48 checks. Baseline command: `python tests/source_checks.py` takes ~0.4s and produces `checked 109 scripts -- names, calls, brackets and autoloads all OK`.
4. **Do**:
   - In `tests/source_checks.py::main`, parse optional positional filter arguments from `sys.argv[1:]` (e.g. using `argparse` or basic list matching).
   - If filter arguments are supplied, match against check names (allowing prefixes like `settings_persist` or full names like `check_settings_persist`).
   - Run only matched checks; report an error and exit with code 2 if a named filter matches no known check.
   - If no arguments are passed, retain the default behaviour of running all checks over all files.
5. **True afterwards**: Running `python tests/source_checks.py check_settings_persist` runs only `check_settings_persist`, outputting `checked 1 check -- OK` in <0.05s, making targeted verification and failure diagnosis fast and token-compact.
6. **Must retain**: Full sweep of all 48 checks when invoked without arguments by `tools/verify.ps1`, GitHub CI, or pre-commit hooks; non-zero exit code if any problem is found.
7. **Verify**: `python tests/source_checks.py check_declarations` passes with 1 check; `python tests/source_checks.py nonexistent_check` exits 2 with unknown check error; `python tests/source_checks.py` runs all checks.
8. **Saving and cost**: Prevents re-running unrelated checks and scanning irrelevant output; saves ~800-2,500 tokens per debugging session on static checks.
9. **Reasoning**: Low risk CLI enhancement; Stop if: `verify.ps1` or CI passes arguments expecting different semantics.
10. **Reviewer entry point**: `tests/source_checks.py::main`.

## Implementation block: E20-2

1. **Outcome and owner**: Candidate Jules task to add a structured failure summary table to `tools/run_tests.py` upon completion of multi-worker runs.
2. **Files**: `tools/run_tests.py`, `tests/test_run_tests_helpers.py` (`free` in preflight).
3. **True now**: In `tools/run_tests.py::run_all`, when a worker subprocess fails (`result.returncode != 0`), `result.stdout` and `result.stderr` are printed immediately under `print_lock`. At the end of `main()`, only `failed: <test_id> -- rerun alone with: python -m unittest <test_id>` is printed. In a run with 20+ modules or parallel threads, the actual failure exception/assertion is hundreds of lines above the bottom of the log. Baseline command: `python tools/run_tests.py --private-user tests.test_heading_helpers tests.test_nonexistent_xyz` prints the traceback in the middle and only the rerun command at the bottom.
4. **Do**:
   - In `tools/run_tests.py`, add a helper function `extract_failure_summary(output: str) -> str` that extracts the last meaningful exception or failure line (e.g. `AssertionError: ...`, `ImportError: ...`, or `FAILED (failures=1)`).
   - In `run_all`, store a tuple of `(test_id, exit_code, summary, seconds)` in `failed_details`.
   - In `main()`, if `failed` is non-empty, print a concise table/summary before or alongside the rerun recommendations:
     ```
     Failures summary:
       - <test_id> (exit <code\>, <seconds\>s): <summary\>
     ```
   - In `tests/test_run_tests_helpers.py`, add unit test coverage for `extract_failure_summary`.
5. **True afterwards**: When running test suites, an agent or developer inspecting the output tail immediately sees why each test failed without searching upward through hundreds of lines of worker thread output.
6. **Must retain**: Full traceback output in the per-test failure log; existing rerun command suggestions; existing exit codes (1 on failure, 0 on success).
7. **Verify**: `python -m unittest tests.test_run_tests_helpers` and running `python tools/run_tests.py --private-user tests.test_heading_helpers tests.test_nonexistent_xyz` shows the error summary at the bottom.
8. **Saving and cost**: Saves ~400-1,200 tokens per failing multi-test run by preventing backward scrolling and transcript rereads.
9. **Reasoning**: Low risk test harness enhancement; Stop if: output formatting breaks automated test log scrapers.
10. **Reviewer entry point**: `tools/run_tests.py::main` and `tests/test_run_tests_helpers.py`.
