## Implementation block: E36-1

1. **Outcome and owner**: Candidate Jules task to extend `tools/func.py` to extract functions from Python source files (`tools/*.py`, `tests/*.py`).
2. **Files**: `tools/func.py`, `tests/test_func_tool.py` (both free in preflight; read-only: `tools/*.py`).
3. **True now**: `tools/func.py` explicitly expects a `.gd` file and parses lines looking for `^(\\t*)((?:static\\s+)?func)\\s+([a-zA-Z0-9_]+)`. Passing a Python file such as `tools/check_docs.py` (1,698 lines) fails because Python functions use `def`, not `func`. As a result, agents inspecting Python tools must either read whole files (up to ~20,000 tokens) or parse AST with ad-hoc bash one-liners. Baseline command: `python tools/func.py tools/check_docs.py check_context_layout` returns non-zero status.
4. **Do**:
   - In `tools/func.py`, update argument parser help to accept both `.gd` and `.py` files.
   - For `.py` files, implement function extraction supporting `def <name>(...)` definitions and extracting the preceding comment/docstring block and indented function body up to the next definition at the same indent level.
   - Print match header (`# <filepath>:<lineno>`) followed by the docstring and function body.
   - Return status 0 if all requested function names are found, or non-zero if any function is missing.
   - In `tests/test_func_tool.py`, add unit tests covering Python function extraction, docstring inclusion, multi-function extraction, and non-zero return on missing functions.
5. **True afterwards**: Running `python tools/func.py tools/check_docs.py check_context_layout` extracts the function and docstring cleanly, allowing targeted reading of Python tools without whole-file loads.
6. **Must retain**: Existing GDScript (`.gd`) extraction regex and behaviour; UTF-8 stream reconfigurations; return status 0 on match and non-zero on error/missing.
7. **Verify**: `python tools/func.py tools/check_docs.py check_context_layout` outputs definition and returns 0; `python -m unittest tests.test_func_tool` passes.
8. **Saving and cost**: Avoids loading 1,000+ line Python tools into context, saving ~1,500-6,000 tokens per query. AST/regex extraction is instantaneous (<0.01s).
9. **Reasoning**: Safe CLI tool extension; Stop if: Python syntax edge cases require heavyweight external dependencies.
10. **Reviewer entry point**: `tools/func.py` and `tests/test_func_tool.py`.

## Implementation block: E36-2

1. **Outcome and owner**: Candidate Jules task to add a dedicated `--list` option to `tools/heading.py`.
2. **Files**: `tools/heading.py`, `tests/test_heading_tool.py` (free in preflight).
3. **True now**: `tools/heading.py` requires two positional arguments: `file` and `heading`. If an agent or script only wants an index of available headings, passing an empty string or mismatched pattern causes a non-zero return and prints headings to `sys.stderr` as an error. Baseline command: `python tools/heading.py AGENTS.md ""` returns non-zero.
4. **Do**:
   - In `tools/heading.py::main`, add optional `--list` argument (`parser.add_argument("-l", "--list", action="store_true", help="list all headings in the file and return 0")`).
   - Make the `heading` positional argument optional when `--list` is specified (`nargs="?"`).
   - When `--list` is provided, print each heading formatted with its level indentation (`{'#' * level} {text}`) to `sys.stdout` and return 0.
   - In `tests/test_heading_tool.py`, add tests asserting that `--list` outputs headings to stdout and returns code 0.
5. **True afterwards**: Running `python tools/heading.py AGENTS.md --list` cleanly prints the document's heading table of contents to stdout with return code 0 without raising tool errors or dumping stderr noise.
6. **Must retain**: UTF-8 stream reconfigurations, ATX heading regex parsing (`HEADING_PATTERN`), fenced code block exclusion (`FENCE_PATTERN`), case-insensitive substring matching for normal queries, non-zero return on missing file or unmatched heading when `--list` is not passed.
7. **Verify**: `python tools/heading.py AGENTS.md --list` returns 0 and prints TOC; `python -m unittest tests.test_heading_tool` passes.
8. **Saving and cost**: Prevents error-handling loops, avoids dumping unintended section bodies, and saves ~200-600 tokens per document navigation query.
9. **Reasoning**: Low risk CLI enhancement; Stop if: breaking positional argument parsing for existing callers (`tools/slice.ps1`).
10. **Reviewer entry point**: `tools/heading.py::main` and `tests/test_heading_tool.py`.
