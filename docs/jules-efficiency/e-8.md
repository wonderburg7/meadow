## Implementation block: E8-1

1. **Outcome and owner**: Candidate Jules task to ensure `tools/prefinish.py::select_modules` selects valid test modules for widely referenced core scripts instead of discarding all tests when none match `test_<stem>`.
2. **Files**: `tools/prefinish.py`, `tests/test_prefinish.py` (free in preflight).
3. **True now**: `tools/prefinish.py` checks `if len(found) > BROAD: found = [t for t in found if t.rsplit("/", 1)[-1].startswith("test_%s" % stem)]`. For `scripts/bee.gd`, 12 test modules mention it, but none are named `test_bee*.py` (tests are named e.g. `test_t2_13_carried_body.py`, `test_t2_14_idle_reason_pure.py`). Thus `found` becomes empty, and `select_modules` selects zero unit tests. Baseline command: `python -c "from tools.prefinish import select_modules; print(select_modules(['scripts/bee.gd']))"` prints `{}`.
4. **Do**:
   - In `tools/prefinish.py::select_modules`, if filtering by `test_%s` prefix yields an empty list when `found` originally had tests, either retain the first `BROAD` most relevant modules or match against test class/function patterns rather than discarding all tests.
   - In `tests/test_prefinish.py`, add test case asserting that a broad file with no `test_<stem>` files retains a bounded subset of tests rather than zero tests.
5. **True afterwards**: Changing `scripts/bee.gd` or `scripts/main.gd` executes a bounded subset of matching unit tests in `prefinish.py` before `finish` is attempted.
6. **Must retain**: Filtering behavior for shared infrastructure such as `tools/godot_compile_check.py` where `test_godot_compile_check.py` exists; fail-fast execution order.
7. **Verify**: `python -m unittest tests.test_prefinish` and `python tools/prefinish.py`.
8. **Saving and cost**: Avoids blind `slice.ps1 finish` invocations that fail in full verification; saves ~1,500-4,000 tokens of diagnosis and rerun cycles per occurrence.
9. **Reasoning**: Low risk, localized tool helper refinement; Stop if: test selection exceeds 15 seconds during prefinish.
10. **Reviewer entry point**: `tools/prefinish.py::select_modules` and `tests/test_prefinish.py`.

## Implementation block: E8-2

1. **Outcome and owner**: Candidate Jules task to add a concise end-of-run failure summary in `tools/run_tests.py`.
2. **Files**: `tools/run_tests.py`, `tests/test_run_tests_helpers.py` (free in preflight; note: check unmerged branch status).
3. **True now**: When multiple test targets fail under `run_tests.py`, the runner prints stdout/stderr as workers finish, followed only by `failed: <id> -- rerun alone with: python -m unittest <id>`. If dozens of tests were run, the exact failure assertion / exception is buried in verbose output.
4. **Do**:
   - In `tools/run_tests.py`, record the primary failure assertion/exception line from worker stderr/stdout for each failing test.
   - At the completion of `run_pool`, print a compact summary listing each failed id alongside its concise failure reason before the rerun commands.
   - In `tests/test_run_tests_helpers.py`, add unit test verifying failure reason extraction and formatted summary output.
5. **True afterwards**: Workers and reviewers reading test output see an immediate failure summary without scrolling through intermediate execution logs.
6. **Must retain**: Full stderr and stdout logging for debugging; exit code 1 on failure.
7. **Verify**: `python tools/run_tests.py --private-user tests.test_heading_helpers test_nonexistent_module` shows concise error reason in final summary.
8. **Saving and cost**: Saves ~300-900 tokens per failing test session by removing the need to re-read or scroll through multi-threaded test runner logs.
9. **Reasoning**: Low risk test harness enhancement; Stop if: parsing output alters subprocess return code handling.
10. **Reviewer entry point**: `tools/run_tests.py::run_pool` and `tools/run_tests.py::main`.
