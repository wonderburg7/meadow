## Implementation block: E4-1

1. **Outcome and owner**: Candidate Jules task to extend `tools/func.py` to extract Python functions and top-level definitions from `.py` files.
2. **Files**: `tools/func.py`, `tests/test_func.py` (free in preflight).
3. **True now**: `tools/func.py` uses `re.compile(r"^(?P<indent>[ \t]*)(?:static\s+)?func\s+(?P<name>\w+)\s*\(")` which fails on Python `def` signatures. Attempting to run `python tools/func.py tools/jules_preflight.py owners` prints `error: tools/jules_preflight.py has no function named 'owners'` and exits with status 1. Agents must resort to full-file reads or arbitrary shell commands.
4. **Do**:
   - In `tools/func.py`, detect whether the target path ends in `.py` vs `.gd`.
   - For `.py`, parse definitions matching `^(?P<indent>[ \t]*)(?:async\s+)?def\s+(?P<name>\w+)\s*\(` and extract preceding docstrings or comments.
   - For `.py`, bound the function end by indentation or next top-level statement.
   - Add unit tests in `tests/test_func.py` asserting extraction of GDScript and Python functions, doc comments, and error exits.
5. **True afterwards**: `python tools/func.py tools/jules_preflight.py owners` prints the doc comment and body of `owners` (18 lines) rather than failing or requiring a 400-line read.
6. **Must retain**: Existing GDScript parsing behaviour, indentation detection, section comment boundaries, UTF-8 console streams, and exit codes (0 on success, 1 on missing).
7. **Verify**: `python tools/func.py tools/jules_preflight.py owners` and `python -m unittest tests.test_func`.
8. **Saving and cost**: Avoids reading 300-800 line tool/test files when only 10-30 lines of a helper function are needed; saves ~1,000-3,500 tokens per query.
9. **Reasoning**: Low risk. Pure utility script with straightforward regex/AST parsing. Stop if Python AST parsing introduces incompatible behaviour or slows down execution.
10. **Reviewer entry point**: `tools/func.py::extract` and `tests/test_func.py`.

## Implementation block: E4-2

1. **Outcome and owner**: Candidate Jules task to compact ownership output in `tools/jules_preflight.py`.
2. **Files**: `tools/jules_preflight.py`, `tests/test_jules_preflight.py` (free in preflight).
3. **True now**: `tools/jules_preflight.py` formats ownership reasons as a flat list joined by `; `. For `scripts/save_game.gd`, this emits: `owned scripts/save_game.gd -- named in NEXTSTEPS.md:65; named in plans/now/code-health.md:2; named in plans/now/code-health.md:327; named in plans/now/code-health.md:360; named in plans/now/code-health.md:390; named in plans/now/difficulty.md:76; named in plans/now/difficulty.md:77; named in plans/now/difficulty.md:94; named in plans/now/difficulty.md:96; named in plans/now/difficulty.md:135; ...` (780 characters, 20 distinct entries).
4. **Do**:
   - In `tools/jules_preflight.py::owners`, group mentions by file path (e.g. `NEXTSTEPS.md: 65`, `plans/now/code-health.md: 2, 327, 360, 390`).
   - Format output compactly: `owned <path> -- planned in <file> (lines ...); changed on unmerged <branch>`.
   - Update tests in `tests/test_jules_preflight.py` to verify formatted grouping and free/owned output assertions.
5. **True afterwards**: Running preflight on heavily referenced core scripts yields clean, grouped output under 200 characters instead of 800+ character repetitive noise.
6. **Must retain**: Identification of exact unmerged branches, plan files, and strict 0/1 exit code contract.
7. **Verify**: `python tools/jules_preflight.py scripts/save_game.gd` and `python -m unittest tests.test_jules_preflight`.
8. **Saving and cost**: Reduces output tokens by ~70% across preflight invocations during task planning and verification.
9. **Reasoning**: Low risk. Text formatting change in standalone preflight tool. Stop if consumers parse line numbers with exact regex matching the old format.
10. **Reviewer entry point**: `tools/jules_preflight.py::owners` and `tests/test_jules_preflight.py`.
