## Implementation block: E4-1

1. **Outcome and owner**: Candidate Jules task to extend `tools/func.py` with cross-script discovery when the exact file is unknown.
2. **Files**: `tools/func.py`, `tests/test_func.py` (free in preflight; read-only: `scripts/*.gd`).
3. **True now**: `tools/func.py` accepts positional arguments `path` and `names [names ...]`. If the function exists in a different file (e.g. `scripts/bee_movement.gd` instead of `scripts/bee.gd`), `python tools/func.py scripts/bee.gd resolve_flight_start` prints an error and exits 1. 89 scripts are under the 700-line threshold and thus omitted from `FUNCTION_MAP.md`, containing 540 functions that cannot be located via the function map index.
4. **Do**:
   - In `tools/func.py`, allow the `path` argument to accept a glob, directory (e.g. `scripts/`), or special keyword `--any` / search all scripts if only function names are provided or path is `scripts/`.
   - When scanning multiple files, search top-level definitions in each `.gd` file, printing `# <path>:<lineno>` followed by docstrings and function body for every match found.
   - In `tests/test_func.py`, add unit tests covering directory search, single-match output, multi-match disambiguation, and exit codes when missing.
5. **True afterwards**: A developer or model seeking a function definition without knowing which script owns it can run `python tools/func.py scripts/ resolve_flight_start` and obtain the exact signature, docstrings, and body without reading full files.
6. **Must retain**: Existing behaviour and exit code contracts when an explicit `.gd` file is provided; stdout/stderr encoding configuration for Windows compatibility; extraction of `#` and `##` doc comments.
7. **Verify**: `python -m unittest tests.test_func` and `python tools/func.py scripts/ resolve_flight_start`.
8. **Saving and cost**: Avoids 500-2,000 tokens of full-file inspection or trial-and-error reads across 105 scripts. Zero runtime cost to game simulation.
9. **Reasoning**: Low risk. Pure Python developer utility. Stop if scanning 105 files adds noticeable latency (>0.5s) on standard disks (currently 105 files total ~28,000 lines, scanned in <0.05s).
10. **Reviewer entry point**: Inspect `tools/func.py::extract` and `tools/func.py::main`. Run `python tools/func.py scripts/bee_movement.gd resolve_flight_start`.

## Implementation block: E4-2

1. **Outcome and owner**: Candidate Jules task to batch path ownership queries in `tools/jules_preflight.py`.
2. **Files**: `tools/jules_preflight.py`, `tests/test_preflight_helpers.py` (free in preflight; read-only: `plans/reference/jules.md`).
3. **True now**: In `tools/jules_preflight.py`, `owners()` loops over `paths` and calls `planned_mentions(root, path, base)` individually for each path:
   ```python
   for path in paths:
       found[path] += [f"named in {mention}" for mention in planned_mentions(root, path, base)]
   ```
   Each call executes `git grep -n -F -e <path> <base> -- <PLANNED>`. Checking 10 files spawns 10 git processes.
4. **Do**:
   - Update `planned_mentions` or add `batch_planned_mentions(root: Path, paths: list[str], base: str = BASE) -> dict[str, list[str]]`.
   - Pass multiple `-e <path>` flags to a single `git grep` execution.
   - Map matching output lines back to their corresponding requested path.
5. **True afterwards**: Querying ownership for multiple files in preflight runs in a single git execution.
6. **Must retain**: Output formatting `"named in <file>:<line>"`, case-sensitivity, and behaviour when no mentions exist.
7. **Verify**: `python -m unittest tests.test_preflight_helpers` and `python tools/jules_preflight.py tools/func.py tools/check_docs.py`.
8. **Saving and cost**: Reduces CLI latency and execution overhead during multi-file preflight checks. Maintenance cost is minimal (~15 lines of Python).
9. **Reasoning**: Low risk. Refactoring internal helper in developer CLI tool.
10. **Reviewer entry point**: Inspect `tools/jules_preflight.py::owners` and `tools/jules_preflight.py::planned_mentions`.
