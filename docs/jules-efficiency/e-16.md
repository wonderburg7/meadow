## Implementation block: E16-1

1. **Outcome and owner**: Candidate Jules task to extend `tools/func.py` with multi-file directory scanning across GDScript files and top-level function extraction from Python files.
2. **Files**: `tools/func.py`, `tests/test_func.py` (`free` in preflight).
3. **True now**: `tools/func.py` requires an existing single `.gd` file path. When inspecting Python tools (`python tools/func.py tools/jules_preflight.py owners`), it reports `error: tools/jules_preflight.py has no function named 'owners'` and exits 1 because its regex matches `func` rather than `def`. When an agent searches for a function whose owning script is unknown, `func.py` cannot scan a directory, forcing agents to read entire modules or perform unrestricted shell greps.
4. **Do**:
   - In `tools/func.py`, allow the `path` argument to accept a directory (e.g. `scripts/` or `tools/`).
   - For a directory argument, scan all `.gd` (or `.py`) files within it for the named function(s), outputting `# <file>:<line>` followed by the doc comment and body for each match.
   - For `.py` files, parse definitions matching `^(?P<indent>[ \t]*)(?:async\s+)?def\s+(?P<name>\w+)\s*\(` and extract leading docstrings/comments and body bounded by outer indentation.
   - Retain standard exit code 0 when all requested names are found, 1 if any name is missing.
   - Add comprehensive unit tests in `tests/test_func.py` verifying both single-file and directory extraction for `.gd` and `.py` files, including docstring extraction and exit status.
5. **True afterwards**: Running `python tools/func.py tools/jules_preflight.py owners` prints the 18-line `owners` function and docstring. Running `python tools/func.py scripts/ _try_role_work` prints the function definition from `scripts/bee.gd` directly without needing prior knowledge of which file contains it.
6. **Must retain**: Existing extraction behaviour for single GDScript files; UTF-8 console streams for Windows compatibility; preservation of `#` and `##` doc comments; exit code 0 for matches and 1 for missing functions.
7. **Verify**: `python tools/func.py tools/jules_preflight.py owners` and `python -m unittest tests.test_func`.
8. **Saving and cost**: Avoids 500-2,500 tokens of file reading per lookup; zero runtime overhead to the game engine or simulation.
9. **Reasoning**: Low risk developer tooling enhancement. Stop if scanning directories adds perceptible latency (>0.2s).
10. **Reviewer entry point**: Inspect `tools/func.py::extract` and `tools/func.py::main`.

## Implementation block: E16-2

1. **Outcome and owner**: Candidate Jules task to compact redundant planned line citations in `tools/jules_preflight.py`.
2. **Files**: `tools/jules_preflight.py`, `tests/test_jules_preflight_helpers.py` (`free` in preflight).
3. **True now**: `owners()` in `tools/jules_preflight.py` formats planned citations by formatting each grep match as `named in {name}:{number}`. For files with many mentions (e.g., `scripts/bee.gd` with 12 citations across `NEXTSTEPS.md` and `plans/now/*.md`), the output repeats `named in ` for every single line number, emitting 530 bytes. For directories like `scripts/`, output expands to 5,205 bytes on a single line.
4. **Do**:
   - In `tools/jules_preflight.py`, group mentions returned by `planned_mentions` by plan file path.
   - Format multiple line citations for the same plan file as `named in <file>:line1,line2` instead of repeating `named in <file>:line1; named in <file>:line2`.
   - Update tests in `tests/test_jules_preflight_helpers.py` to cover the compacted output formatting while verifying that ownership determination (`free` vs `owned`) is completely unchanged.
5. **True afterwards**: `python tools/jules_preflight.py scripts/bee.gd` outputs 305 bytes instead of 530 bytes. `python tools/jules_preflight.py scripts/` outputs 941 bytes instead of 5,205 bytes, saving 4,264 bytes (~1,000 tokens) on a single ownership check.
6. **Must retain**: Precise list of referenced plan files and line numbers; clear attribution of ownership; exit code 0 for free paths and 1 for owned paths.
7. **Verify**: `python -m unittest tests.test_jules_preflight_helpers` and `python tools/jules_preflight.py scripts/bee.gd`.
8. **Saving and cost**: 40-80% reduction in preflight stdout size across multi-mention queries; zero maintenance cost; backwards compatible with human and automated readers.
9. **Reasoning**: Low risk string formatting compaction in tooling. Stop if downstream consumers require `named in` before each individual line number.
10. **Reviewer entry point**: Inspect `tools/jules_preflight.py::owners`.
