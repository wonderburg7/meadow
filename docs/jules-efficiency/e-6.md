## Implementation block: E6-1

1. **Outcome and owner**: Candidate Jules task to have slice start routing output state the exact `.claude/rules/*.md` contract documents that apply to the slice's files.
2. **Files**: `tools/slice.ps1` or a helper `tools/slice_rules.py`, `tests/test_slice_rules.py` (free in preflight; read-only: `.claude/rules/*.md`).
3. **True now**: `slice-worker.md` § "Routine" step 2 states: "The path's `.claude/rules/` file applies: read the one for the area you edit (`simulation.md`, `saving.md`, `performance.md`, ...)". However, `tools/slice.ps1 start` only prints the slice's plan section read command. Subagents often skip reading the rules or read unnecessary rules files to determine which one governs their files. Baseline command: `python tools/heading.py plans/reference/slice-worker.md "Routine"`.
4. **Do**:
   - Create a helper `tools/slice_rules.py` (or extend `tools/backlog.py`) that matches a slice's file list against YAML frontmatter `paths:` in `.claude/rules/*.md`.
   - In `tools/slice.ps1 start` (or `tools/slice_lifecycle.py`), print: `Applicable rules: python tools/heading.py .claude/rules/<rule>.md "<heading>"`.
   - Add unit tests in `tests/test_slice_rules.py` asserting correct mapping between script paths (e.g. `scripts/bee_foraging.gd` -> `.claude/rules/simulation.md`, `scripts/save_game.gd` -> `.claude/rules/saving.md`).
5. **True afterwards**: A slice worker starting on `scripts/bee_foraging.gd` is given the exact rule file and section to read upfront, preventing unguided exploration and rule rediscoveries.
6. **Must retain**: Existing slice start output structure, git worktree lifecycle behavior, and exit statuses.
7. **Verify**: `python tools/slice_rules.py scripts/bee.gd` prints `.claude/rules/simulation.md`.
8. **Saving and cost**: Avoids 1-2 exploratory tool calls (~800-1,800 tokens) per slice start across dozens of planned slices.
9. **Reasoning**: Low risk. Read-only path-matching utility with fast execution. Stop if frontmatter parsing adds noticeable overhead.
10. **Reviewer entry point**: `tools/slice_rules.py` and `tests/test_slice_rules.py`.

## Implementation block: E6-2

2. **Files**: `tools/prefinish.py`, `tests/test_prefinish.py` (owned by code-health/lifecycle plans).
3. **True now**: `prefinish.py` runs boot check and unit tests naming changed files, but does not explicitly run contract static checks (like `check_gameconfig_writes` from `tests/source_checks.py`), allowing contract regressions to reach `tools/slice.ps1 finish` before failing.

5. **True afterwards**: Workers running `prefinish.py` catch contract regressions within 2 seconds instead of waiting for full verification logs.
6. **Must retain**: All existing prefinish checks, exit codes, and doctor diagnostics.
7. **Verify**: `python tools/prefinish.py` runs contract checks and exits 0 on clean worktrees.
8. **Saving and cost**: Saves substantial diagnostic cycles and re-runs during slice closeout.
9. **Reasoning**: Medium risk as `prefinish.py` is in the critical verification path. Needs coordination in `plans/now/code-health.md`.
10. **Reviewer entry point**: `tools/prefinish.py`.
