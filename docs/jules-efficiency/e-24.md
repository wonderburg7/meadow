## Implementation block: E24-1

1. **Outcome and owner**: Candidate Jules task to extend `tools/func.py` with directory-wide function lookup across `scripts/*.gd`.
2. **Files**: `tools/func.py`, `tests/test_func_tool.py` (both free in preflight; read-only: `scripts/*.gd`).
3. **True now**: `tools/func.py` requires two positional arguments: `path` and `names [names ...]`. If the function exists in a different script (e.g. `scripts/bee_movement.gd` instead of `scripts/bee.gd`), `python tools/func.py scripts/bee.gd resolve_flight_start` fails with exit code 1. 89 scripts are under the 700-line threshold and omitted from `FUNCTION_MAP.md`, containing over 500 functions that cannot be resolved via the index. Baseline command: `python tools/func.py scripts/bee.gd resolve_flight_start` returns exit code 1 and error output.
4. **Do**:
   - In `tools/func.py`, allow the `path` argument to accept a directory (e.g. `scripts/` or `scripts`).
   - When `path` is a directory, iterate over all `*.gd` files in sorted order within that directory, extract matching definitions for each named function, and print the match header (`# <filepath>:<lineno>`) followed by doc comments and body.
   - If any named function is not found in any file in the directory, record it as missing and exit with code 1; if all named functions are found, exit with code 0.
   - In `tests/test_func_tool.py`, add unit tests asserting directory-based function extraction, multi-file discovery, and exit code 1 when a function is absent across the directory.
5. **True afterwards**: Running `python tools/func.py scripts/ resolve_flight_start` locates and extracts the function from `scripts/bee_movement.gd` without requiring prior knowledge of the script file or full-file reads.
6. **Must retain**: Existing behaviour when `path` is an explicit file; UTF-8 stdout/stderr reconfiguration; docstring extraction (`#` and `##`); exit code 0 on full success and 1 on any missing function.
7. **Verify**: `python tools/func.py scripts/ resolve_flight_start` exits 0 and prints the function definition; `python -m unittest tests.test_func_tool` passes.
8. **Saving and cost**: Avoids 300-1,500 tokens of broad grep noise or full-file context reads across 105 scripts. Scanning all scripts takes <0.05s on local disks.
9. **Reasoning**: Low risk CLI enhancement; Stop if: scanning directory introduces perceptible latency (>0.5s).
10. **Reviewer entry point**: `tools/func.py::main` and `tests/test_func_tool.py`.

## Implementation block: E24-2

1. **Outcome and owner**: Candidate Jules task to add native `--all-unit` module discovery to `tools/run_tests.py`.
2. **Files**: `tools/run_tests.py`, `tests/test_run_tests_helpers.py` (both free in preflight).
3. **True now**: `tools/run_tests.py` requires callers to pass test module names explicitly as positional arguments. As a result, agent documentation, prompts, and sessions execute a 138-character bash pipeline:
   ```bash
   modules=$(ls tests/test_*.py | sed 's#^tests/#tests.#; s#\.py$##' | grep -v -x -e tests.test_slice_lifecycle -e tests.test_two_lane_closeout)
   python tools/run_tests.py --private-user --label "unit tests" $modules
   ```
   This pipeline is brittle, consumes token overhead across prompts and instructions, and fails on Windows PowerShell 5.1 without manual translation. Baseline command: `python tools/run_tests.py --help` shows positional `[modules ...]`.
4. **Do**:
   - In `tools/run_tests.py`, add a helper function `discover_unit_modules(root: Path) -> list[str]` discovering all `tests/test_*.py` files, excluding slow/lifecycle tests (`tests.test_slice_lifecycle`, `tests.test_two_lane_closeout`).
   - In `tools/run_tests.py::main`, add `--all-unit` flag. When passed (or when no modules are supplied and `--all-unit` is set), populate `modules` with `discover_unit_modules(ROOT)`.
   - In `tests/test_run_tests_helpers.py`, add unit tests asserting that `discover_unit_modules` returns the expected set of modules with lifecycle tests excluded.
5. **True afterwards**: Sessions and scripts run `python tools/run_tests.py --private-user --all-unit` directly without requiring intermediate shell pipelines or platform-specific syntax.
6. **Must retain**: Existing module-specific arguments, case expansion (`--cases`), worker pool threading, timings persistence, and game test skip logic (`--game-tests-since`).
7. **Verify**: `python tools/run_tests.py --private-user --all-unit` runs unit test suite cleanly; `python -m unittest tests.test_run_tests_helpers` passes.
8. **Saving and cost**: Eliminates repeated shell pipeline syntax across agent prompts and instructions, saving ~150-300 tokens per test run invocation and preventing cross-platform shell syntax errors.
9. **Reasoning**: Low risk test runner feature; Stop if: module discovery alters test execution order in a way that breaks isolated test cases.
10. **Reviewer entry point**: `tools/run_tests.py::discover_unit_modules` and `tests/test_run_tests_helpers.py`.
